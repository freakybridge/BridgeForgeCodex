# GPT-6 骨架升级：第 1 轮审计结论

## 记录性质与结论

本报告按用户“把第 1 轮审计的结论先落盘”的明确要求，保存本对话最初的兼容性审计结果。它是审计记录，不是已确认需求卡、实施授权、发布收据或用户验收。

第 1 轮结论：需要针对性校准骨架和 Skill 的行为规则，不需要全面重写，也不需要将模型名称批量替换为 GPT-6。主要风险是只读取证前提前停止、已授权后重复确认，以及同时生效的指令相互冲突。

初审由主对话和独立 `review-auditor` 共同完成。本报告依据已产生的文件读取、搜索和独立审计结果整理；落盘时未重新执行模型审计、构建、回归或 runtime smoke。后续计划审计对初审部分表述已有修正，单独记录在第 5 节，禁止将初审建议不加区分地当作最终实施清单。

## 2. 第 1 轮主要发现

### A01：范围澄清阻断了必要的只读取证

- 证据：[Template AGENTS 第 96 行](../../../templates/AGENTS.md)、工厂根 AGENTS 同节，以及 [plan 第 20 行](../../../skills/plan/SKILL.md)，要求在读取仓库或只读评估之前停止并询问范围。
- 风险：事实可以从本地核验时，仍可能先向用户提问；GPT-6 对流程指令更敏感，可能放大这类停顿。
- 初审建议：允许先执行安全、必要的只读核验，再询问会实质改变结果的问题。
- 建议承载：公共 Template 与自身镜像、plan Skill；属于通用骨架行为。
- 误伤风险与验证：不能因此取消真正模糊的大需求澄清；需同时验证“只读审计直接调查”和“模糊大需求不擅自实施”。
- 状态：等待用户采纳；未写入规则；未实现。

### A02：缺少明确的授权复用与 Skill 暂停解释

- 证据：[Template AGENTS 第 85—92 行](../../../templates/AGENTS.md)定义模型继承与主、子 Agent 分工，但没有明确用户已给授权如何优先于默认流程，也没有要求指出导致暂停的具体 Skill 条款。
- 风险：Skill 的流程要求可能被理解为需要重新获取已经给出的授权；用户难以判断是确有阻塞还是流程重复。
- 初审建议：补充用户指令与 Skill 流程的关系；Skill 导致暂停时说明具体文件、条款及适用原因。
- 建议承载：公共 AGENTS 的分工与授权红线，流程细节留在相应 Skill，不复制完整规则到所有文件。
- 误伤风险与验证：禁止写成普通开工授权可覆盖平台安全、资产所有权或任意外部副作用；需验证仅确认需求与明确授权实施两类输入。
- 状态：等待用户采纳；未写入规则；未实现。

### A03：confirm 与 develop 存在重复开工确认风险

- 证据：[confirm 第 68 行](../../../skills/confirm/SKILL.md)选项为“准确，写入需求卡并继续”；[develop 第 34—43 行](../../../skills/develop/SKILL.md)读取有效卡后仍要求询问是否开始开发。
- 风险：用户已经明确说“开始”时，流程仍可能再次停止；但只确认需求本身又不能被视为已经授权编码。
- 初审建议：已有明确、仍有效的开工授权时直接推进，避免重复确认。
- 建议承载：confirm / develop 的交接规则及相关 references。
- 误伤风险与验证：不能仅因有需求卡便自动开工；需覆盖“需求准确但暂不实施”和“有效卡加开始”两种相反场景。
- 状态：等待用户采纳；未写入规则；未实现。

### A04：失败停止阈值存在两套表述

- 证据：用户级 `C:\Users\bridg\.codex\AGENTS.md:39` 要求同一 Bug 修复失败两次即停；公共 AGENTS 第 107 行写前三次修改失败后、第四次前停止。
- 风险：同时生效的阈值不同，实际停止行为不够清晰。
- 初审建议：明确唯一有效口径及适用范围，避免多处独立维护次数。
- 建议承载：产品公共规则与本机个人规则分别核定；个人 AGENTS 不属于骨架安装器可自动覆盖的目标。
- 误伤风险与验证：不得借统一规则自动放宽用户更严格的个人约束；验证停止条件、用户主动要求 escalate 和后续授权恢复。
- 状态：等待用户采纳；未写入规则；未实现。
