## 3. 目标流程

| 操作 | 简化后的责任 | 不自动执行的工作 |
|---|---|---|
| develop | 明确本次范围和完成标准 → 实现 → 本次必要验证/适用审查 → 受管处理受影响子包版本 → 交付结束；已有明确决定和有效验证直接复用 | 不重复访谈或为建立长期证书再跑整组检查，不要求无关历史证据清零，不自动接续 summary、Git 保存或 release |
| 普通 git-sync | 按授权安全提交和同步，保留现有 Hook 与 Git 保护 | 不升版，不补做 develop，不转入 release |
| git-sync release | 复用已有授权和决定，核对累计实际改动、版本和必要发布条件 → 升主程序版本 → 安全同步并公告全部子包累计变化 | 不核对旧机器环境能否重现长期测试证书，不重复准备和审阅同一事实，不自动补做开发、无关测试或验收 |

沿用已确认的版本分工：develop 处理受影响子包，release 处理主程序且不再次升子包；本次不擅自改为所有对象都在 release 升版。0.x/1.x 判级、版本连续性、重复运行不重复升版及既有自动稳定标准保留；稳定判断使用本次适用条件，不恢复长期环境证书依赖。

本次验证接受已有仍适用的实际结果，发现真实输入变化时按影响补验。测试未执行、失败、超时或结果未知均不得记为通过。受管版本处理负责版本计划、写入与失败恢复，不再强制承担第二套测试执行与长期认证职责。

develop 与 git-sync release 都应在约定职责完成、取得必要结果后结束。重复核验须有输入变化、证据矛盾或实际失败等具体理由；不以切换步骤、Skill、进程或会话为由重新询问已明确事项，也不将缺少无关历史状态作为持续追加工作的理由。必要的短期防漂移核验和现有授权保护保留。

方案 A 当前仍以根 AGENTS 原文为准；本卡中的目标流程尚未完成切换，不因文档保存或源码部分实现私自撤销、改写或替换方案 A。最终切换存在条款冲突时必须交用户决定。
