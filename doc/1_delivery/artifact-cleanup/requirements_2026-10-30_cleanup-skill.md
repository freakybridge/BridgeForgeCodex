## 4. 执行行为与安全边界

以下是实现与验收要求，不代表已有工具能力：

1. 显式调用才执行，仅作用于已核验的当前项目根；不建立定时任务，不增加启动或提交时自动清理。
2. 先在内存中确定删除集合、保护集合及项目边界，再执行同一次调用。正常路径无需用户再次批准；可提供只读预览，但不强制用户先手动预览再调用执行。
3. 删除前校验实际绝对路径、项目身份和包含关系，拒绝越界、根路径误判及符号链接、junction、重解析点引起的跨边界遍历。预检发现边界不可信时不开始删除；执行中发生路径漂移时停止受影响操作并报告。
4. 若有活动构建、测试或受管事务会被清理破坏，阻断相关清理并说明原因；不自动杀进程、移除活动锁或删除恢复中的事务。占用、权限或 I/O 失败须准确报告已删与未删范围；不宣称递归删除具备整体回滚能力。
5. 工厂当前工具及其关联收据保留，由当前项目受管入口直接执行，不采用外部受管工具清理方案。验证清理后工具仍可用、保留文件字节不变，不以重新构建掩盖误删。历史识别依据不足时保留并报告，不按文件时间或目录名猜测它已过时。
6. 结果区分完整成功、部分完成与阻断，列明失败路径及原因；如报告释放空间，使用实际可验证统计并标注口径。收据不写回刚清空的目录导致产物重新出现；默认在调用结果中返回摘要。

## 6. 验收计划

所有删除验证先在项目指定测试任务目录的隔离样本内执行，遵循 TODO-048 落地后的测试输出合同，不清理真实项目来证明测试通过。

| 验收面 | 必须覆盖 |
|---|---|
| 前置依赖 | 旧布局、未迁移或合同证据不足时不执行删除；新合同下正常执行 |
| 保留范围 | config/download 中嵌套、隐藏、中文文件字节保持；`.deps/` 及根外源码、配置、锁文件和资料不变 |
| 删除范围 | runtime 根文件、tests、缓存、输出及非保留运行状态删除；build 只删除已确认历史编译，当前产物保留；近似目录名不误保留 |
| 路径安全 | 大小写、分隔符、跨工作目录启动、路径漂移、符号链接及 Windows junction/reparse 点不导致越界或保护目录误删 |
| 异常与并发 | 活动事务、构建占用、权限错误和删除中断；真实报告部分成功，不自动杀进程、不承诺回滚 |
| 幂等与零写入 | 空目录、目录不存在、重复调用；预览不删除、不建目录、不写锁、缓存或收据 |
| 工具保留 | 工厂当前工具及收据不变，当前项目入口可完成并返回，清理后 self-test 仍可用；下游 `.deps/` 工具保留 |
| 分发与体验 | 模板、分发、dogfood 与引用一致；正常调用不逐项确认；报告可核对，无后台定时清理 |

选择覆盖上述风险的定向测试及实际 CLI smoke，独立审查聚焦误删边界、自身执行器和恢复入口；不预设全量回归。实现通过、用户验收、真实下游、用户级安装和自然调用分别报告。
