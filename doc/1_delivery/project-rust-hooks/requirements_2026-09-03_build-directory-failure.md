# 骨架临时构建路径失效修复确认卡

## 授权与预算

用户要求修复骨架并 Git-sync Forge，然后将新版本安装到 Assist；已于本轮以“同意”确认范围和预算。M 级：最多 60 分钟、约 20k 新增 token（估算，未实测）、最多 1 名 review-auditor、2 轮验证。开始时间 2026-09-03 16:29:49 +08:00。发现根因无法确认或预计超预算时停止，禁止猜测性补丁。

## 已核实事实与非目标

1.12.2 正式 apply 在临时目录编译骨架 Hook 时，Cargo 写入 `.fingerprint/bridgeforge-hook-97412f22e4783ff7/invoked.timestamp` 返回 Windows 路径不存在；尚未进入项目写入事务。安装前后 19 个目标及保留文件哈希一致，Assist 仍为 1.12.0。

同版本计划构建曾成功；工具链 doctor 通过。静态调用链显示同步等待 Cargo 完成后才清理本次临时目录，尚不能据此确认外部删除者或判定骨架代码缺陷。早先并发测试有临时文件缺失，相关性尚未证明。

不改 Assist 业务源码、活库、镜像、业务版本或 Hook 信任状态，不提交 Assist；不修改系统清理、杀毒和全局 Git/Cargo 配置，不用自动重试掩盖原因。诊断文件仅存本机，不向公开仓库提交私人路径、文件操作追踪或活库资料。

## 拟实施与传播四问

先对隔离构建收集证据并确认根因，再确定构建生命周期的最小补丁及回归；不得预先断言临时目录是被清理软件删除。拟涉及骨架构建链、对应测试与说明，最终以根因证据锁定。

若证实为产品缺陷，属于产品层通用修复；需要 patch 版本和 `[product]` CHANGELOG；同步 Template 与自身 dogfood，不对工厂执行下游 apply 或写骨架版本戳。发布仅通过 Forge 自带 Git-sync，随后通过官方 updater 和 CLI 安装 Assist，遵守计划指纹及统一风险确认。
