# AGENTS.md 草案持续迭代验证确认卡

> 状态：已中断，未验收  
> 确认日期：2026-08-27  
> 任务规模：L（多轮只读评审与 proposal 修订）

## 用户持续授权

用户要求主对话自行循环“debate -> 输出修订稿 -> debate -> 输出修订稿”，直到交付一个通过验证的版本。该授权仅覆盖当前 proposal 专题，不覆盖真实骨架、发布、Git 提交或跨项目写入。

## 滚动目标

对每一版候选分别验证：

1. 是否足够精简。
2. 是否足够人类友好。
3. 相对现行工厂与 Template 是否存在语义损失。

只有三个议题同时通过，且静态检查没有阻断项，循环才结束。每版的行数、规则数、文件清单和新增证据写入对应 debate 记录；候选版本变化不会使本卡失效。

## 非目标

- 不修改真实根 `AGENTS.md`、`templates/AGENTS.md`、README、Hook、Skill、manifest 或同步器。
- 不执行真实下游写入、runtime 发布、commit 或 push。
- 不把静态 proposal 验证冒充真实运行时验收。

## 每轮规则

- 两个独立 agent 分别担任方案辩护者和反方审计者，默认两轮，核心分歧未收敛时才进入第三轮。
- 每轮必须读取现行真实载体、当前 proposal 和上一轮 debate；禁止只看摘要。
- 每轮必须分别裁定三个议题，并引用文件与行号。
- 语义审计必须检查 owner 是否真实存在、何时加载、是否有硬闸；未来计划不得冒充已完成迁移。
- 每轮结论直接用于下一版 proposal 修订，无需再次向用户确认。
- 修订后必须验证公共区一致性、链接、BOM、标题合同、格式和项目结构，再启动下一轮独立 debate。

## 通过标准

- 精简：根文件只保留跨目录、不能完全机判或高损害的稳定边界；目录细则均有真实草案载体；无纯实施说明和重复 owner。
- 人类友好：首次阅读路径清楚；每条只有一个主要判断；低频术语有中文入口或精确链接；无模糊跳转；独立审计认为五分钟复述标准可通过。
- 语义完整：现行“必须/禁止”全部映射到确定 owner，适用范围、主体、强度、触发与例外没有静默削弱。
- 静态验证：公共区逐字一致、链接完整、无 BOM、项目区兼容、`git diff --check` 通过、项目结构无 errors。

## 循环预算与停止点

- 每个 debate 周期预算：45 分钟、约 20k 新增 token（未实测）、2 个 agent、默认 2 轮、1 次主对话静态核验。
- 同时运行的评审 agent 最多 2 个；不扩张到实现 agent。
- 用户已授权自动进入下一周期，不需要逐版确认。
- 同一阻断连续三个周期仍不能消除、需要修改真实骨架才能取得证据，或需要新的外部授权时停止并报告。

## 风险

- 为消除语义损失补回过多常驻文字，可能重新失去精简目标。
- 为降低行数下沉过度，可能形成规则真空或不确定加载。
- 静态文本可读不等于真实首次读者或 runtime 已通过；最终报告必须明确证据边界。
