## 范围与实现计划

1. 修改共享 summary 入口与模式 references，沿用现有文档布局、TODO 总表和去重规则。switch 使用相对路径，说明代码同步和本机缓存不能随交接文档自动恢复。
2. 删除 snapshot / resume Skill 源码及分发登记；受管升级沿用账本和旧 hash 清理原版已安装副本，自定义副本按既有保留规则处理。不手工删除本机用户目录。
3. 移除自动/手动会话状态快照、列表选择、启动提示和相关注册；保留历史 .runtime/session_state 文件，不影响 Stop 的其他功能、Native Memory 和 Git 事务快照。
4. 更新 autopilot、spinoff、find-doc、develop 及操作文档；spinoff 保持拆前置任务职责，改用 doc 交接，不自动新建对话或扩大授权。
5. 发布准备支持项目显式声明的记录类 Markdown：只做轻量文档校验并绑定本次提交内容，不因经验、交接、验收和 TODO 记录变化重新编译。源码、Skill、配置、构建输入或未声明文件变化仍使准备失效；文档检查不等同独立语义审计。
6. 同步 Rust dogfood、分发 manifest 和必要索引；验证退役无写入、旧历史不删除、其他 Hook 保留、文档更新发布零构建、保护边界和并发变化，再进行独立复核。

## 规模、预算与传播

- M 级：Skill 路由与少量 Rust 合同变更，主对话实现，最多一个 review-auditor 独立复核；20k 新增 token 估算 / 最多两轮验证。用户在本次开发明确将默认 45 分钟扩至 75 分钟，以覆盖完整开发检查和目标构建；累计时间不重置。token 未实测；本机只有旧模型临时系数，不套用为当前配置的周额度预测。预计超预算时报告剩余项，不静默扩张。
- 产品通用能力进入 skills/、templates/ 并同步 dogfood；工厂文档豁免清单只在自身配置。发布时升级版本并记录 CHANGELOG，本轮不预写。
- 完整准备包含项目已规定的检查与目标构建；其耗时计入开发。性能只认用户输入到最终回复，不将 CLI 耗时冒充端到端结果。

## 验收与未验证边界

- 三模式输出真实可点击文档，重复调用不重复记账，不伪造验收或测试证据。
- 自动和手动状态快照入口退役，旧文件逐字保留；Stop 的项目索引和高耗时提醒继续工作。
- 原版已安装退役 Skill 能经受管分发移除；自定义内容不得无依据覆盖或删除。
- 允许的经验/交接/TODO 文档变化通过轻量校验后复用产物；配置、源码、Skill、非法文档、并发改变和提交 Hook 改写仍受保护。
- 真实下游、另一台机器接续、用户级正式分发和真实发布耗时需要各自实际证据；本轮不假称已通过。
