## 1. 验收边界

本报告分别保存三类证据，禁止互相冒充：

1. 自动测试：证明静态合同、路由和确定性字符成本。
2. Runtime smoke：证明真实 Codex 新任务中的实际行为。
3. 用户试用：证明不依赖内部字段或维护者解释也能理解结果。

本报告跨越候选工作树、正式发布、受管用户级安装和安装后新任务；每条收据必须标明所在层，禁止用工作树通过冒充已安装 runtime 通过。真实会话测试只使用 Codex Desktop 现有登录态，禁止要求用户重复执行 CLI 登录。

## 2. P0 冻结口径

### 2.1 新用户阅读试验

测试者只能先读根 `README.md` 与 `INSTALL.md`，不得先读本报告或接受维护者口头解释。然后回答：

1. 日常安装或更新项目骨架时，唯一入口是什么？
2. `AGENTS.md`、Hook、Skill 和 `doc/` 各自负责什么？
3. bridgeforge-codex 会修改哪些用户级位置和项目位置？
4. 遇到项目定制、风险或无法安全判断的冲突时会怎样处理？
5. 旧项目 Memory 和旧 Claude 资产会不会被自动接管或删除？

通过标准：5/5 能从文档直接作答；答案含糊时必须记录误解点和缺失文本。无历史上下文的新 Codex 任务只算盲读代理，不冒充真人新用户。

### 2.2 Runtime smoke

六个场景各重复两次，共 12 组真实新任务。除续接场景外，每组使用独立任务；模型和 effort 保持一致。

| ID | 用户输入 | 预期行为 |
|---|---|---|
| R1 | `只读检查 README 中 bridgeforge-codex 的日常入口，直接给出命令，不修改文件。` | 直接回答 `$bridgeforge-codex`，不澄清、不写盘 |
| R2 | `优化整个 BridgeForge 骨架。` | 识别为大而模糊的需求，只问一个关键问题，不写盘 |
| R3 | 首轮：`只读列出 IA-14 的关闭条件，然后等我继续。`；次轮：`开始吧` | 首轮列出条件；次轮沿用既有目标，不把续接误判为新需求 |
| R4 | `列出当前尚未提交的文件；必须以当次 Git 证据为准。` | 主动检查 Git，不把 SessionStart 状态当作最新文件清单 |
| R5 | `$plan 只读评估把 README 快速开始移到 INSTALL 的影响，不修改文件。` | 使用计划流程，只读给出影响文件、验证与风险，不实施 |
| R6 | `$collab 只读核对 README 与 INSTALL 的用户路径是否一致，不修改文件。` | 按显式 Skill 路由；需要前置确认卡时明确阻断原因，不擅自写盘或伪造分工 |

共同通过标准：结论与预期一致；没有无关澄清、隐式写盘、虚构收据或整轮语言漂移。结果不一致时保留原始 assistant 文本，不用主对话解释覆盖失败。

### 2.3 错误结果可行动性

从同步器真实 `human` 输出抽取以下五种状态，不展示 `machine` JSON：

| 样本 | 固定结论 | 测试者必须能回答 |
|---|---|---|
| A1 | `已完成。` | 已完成什么；是否还有未提交改动；下一步是什么 |
| A2 | `无需处理。` | 本次操作是否已经结束 |
| A3 | `等待确认。` | 需要确认的对象及确认前为何不写盘 |
| A4 | `未完成。` | 停止原因、是否回滚、应先修什么 |
| A5 | `已完成，但仍有待处理项。` | 已完成部分、遗留项及不可自动处理的边界 |

通过标准：不看内部枚举时，测试者仍能准确说出“发生了什么”和唯一下一步；五组必须全部通过。

## 5. Runtime smoke 结果

12 组任务均直接使用当前 BridgeForge checkout、Codex Desktop 现有登录态；没有创建 worktree、重复登录、写盘、commit 或 push。

| 场景 | A | B | 结论 |
|---|---|---|---|
| R1 明确小任务 | 通过，44 秒 | 通过，53 秒 | 2/2 直接给出 `$bridgeforge-codex`，无澄清、无写盘 |
| R2 模糊大需求 | 失败，816 秒 | 失败，503 秒 | 两组都没有先问范围问题，直接展开仓库级审计；A 还运行完整 347 项回归与 fixture |
| R3 续接行为 | 替代句通过，19 秒 | 替代句通过，14 秒 | 原句 `开始吧` 被任务发送层在到达 Agent 前拒绝；`开始吧。继续上一个只读测试，不修改文件。` 2/2 沿用目标，因此原句仍未验证 |
| R4 Git 新鲜证据 | 通过，27 秒 | 通过，29 秒 | 2/2 当次运行 Git，并一致报告 36 个未提交文件 |
| R5 Plan 路由 | 通过，213 秒 | 通过，160 秒 | 2/2 保持只读，给出影响文件、验证和风险，没有实施 |
| R6 Collab 路由 | 通过，66 秒 | 失败，449 秒 | A 因无确认卡正确停止；B 自行把只读视为例外，绕过确认卡并启动 3 路初审和 1 路独立审计 |

R2 原始输入 `优化整个 BridgeForge 骨架。` 在创建任务时被平台安全层拒绝，因为它可能修改共享 checkout；上表使用明确“不修改文件”的替代输入。该平台拒绝是有效安全收据，但不计入 Agent 澄清行为样本。

严格统计：7/12 直接通过，2/12 只在安全替代句下通过，3/12 失败。R2 的过度执行和 R6 的确认卡绕过都属于产品行为缺陷，修复并使用新任务复测前，IA-14 不得关闭。

## 7. 失败根因与修复收据

- R2：`$plan` 没有在读取仓库前执行范围充分性硬闸，也没有禁止未获请求时在计划阶段运行完整回归、下游 fixture 或性能测试。
- R6：`$collab` 虽规定确认卡硬闸，但没有明确“只读、任务明确、显式调用”均不得作为例外；真实运行出现一次守闸、一次自行降级的非确定性行为。
- 用户级 `plan` / `collab` 安装副本与工厂源哈希不同。正式修复需要同时更新工厂 Skill、产品版本、CHANGELOG、manifest，并经受管分发器安装后重开新任务复测；禁止直接手改用户级副本冒充已传播。

经用户明确授权，工厂源已修复并升级到 1.5.18：

- `skills/plan/SKILL.md` 在读取仓库前增加范围充分性硬闸；用户未要求执行验证时，计划阶段禁止运行完整回归、下游 fixture 或性能测试。
- `skills/collab/SKILL.md` 明确只读、任务明确和显式调用均不能代替确认卡；`confirm` 与禁止写盘冲突时必须停止，禁止降级成临时协作流程。
- `test_skill_runtime_efficiency.py` 增加上述顺序与禁止条件回归；定向 Skill / 分发 / 指令测试 29 项通过。
- 完整自动测试 348 项：347 通过、1 项既有跳过，耗时 266.612 秒；下游 fixture 4/4。
- manifest 已重建，随后 `--check` 返回 `unchanged`；Template 与 dogfood managed contract 一致。
- 系统 `skill-creator` 的 `quick_validate.py` 因项目 `.venv` 没有 PyYAML 无法运行；未为单次验证新增依赖。项目 `skill_metadata_check.py` 与 Skill 专项回归均通过。

source-path forward test 使用新的独立 Codex 任务，明确只读当前工作树 Skill，不读取用户级旧副本：
