# IA-08 Hook 上下文测试报告

> 状态：P0–P1 与四组件桌面端 A/B 已完成；Clarify / Focus / 项目 Memory 已退役，Show State 会话级保留，并已整体传播到真实工厂 1.5.13；待真实业务下游与全新会话 runtime smoke
> 测试对象：`refactored-project` 候选镜像与真实工厂 1.5.13
> 日期：2026-08-30

## 1. 测试边界

本轮只测量现有行为，不修改 `AGENTS.md`、Hook 注册、dispatcher、Memory 路由或任一产品 Hook。测量器直接加载 Template 中的真实 Hook 实现；Focus 状态写入临时目录，Git 状态和 Memory 候选使用固定夹具，避免污染候选工作区。

字符数是精确值；真实 token 尚未测量。字符数不得冒充模型 token。P2 使用桌面端现有登录态完成隔离行为 A/B；App 任务收据不提供 token 用量，因此仍不能给出真实 token 成本。

## 2. 样本

- 32 条独立用户消息：8 条续接、8 条明确小任务、6 条明确大任务、6 条模糊大需求、4 条 Skill / slash 命令。
- 3 组七轮 Focus 触发序列：正常深入、用户明确换题、机械式连续执行；共 21 轮。
- 12 组 Focus 桌面端行为配对：6 个场景各重复 2 次，共 24 个隔离任务。
- 每条消息都预先标注 `clarify_expected`、Git 状态相关性和 0 / 1 / 5 个 Memory 候选档位。

样本是用于定位明显结构问题的受控基线，不代表真实用户输入的总体分布。

## 3. 确定性结果

### 3.1 Clarify

| 指标 | 数量 |
|---|---:|
| 应提醒且实际提醒 | 6 |
| 不应提醒但实际提醒 | 19 |
| 不应提醒且未提醒 | 7 |
| 应提醒但漏掉 | 0 |

- 召回率为 100%（6/6），但精确率只有 24%（6/25）。
- 8 条明确小任务全部触发，6 条明确大任务全部触发。
- 8 条续接消息中有 5 条触发；`开始吧`、`进入下一项`、`先处理卡点#1`、`开始 IA-08` 等没有被续接词表识别。
- 每次提醒固定注入 66 个字符。

这证明当前字符串 gate 是一个高召回、低精度的候选提醒器；尚不能证明提醒对 Agent 行为没有收益。

### 3.2 Show State

- 32/32 条消息都注入状态行，每次 80 个字符。
- 按测试标签，5 条任务直接需要 Git 状态，27 条与 Git 状态无直接关系。

这证明它是固定上下文成本；是否对安全判断产生间接收益仍需 A/B 验证。

### 3.3 Memory

| 候选数 | 单次注入字符 |
|---:|---:|
| 0 | 45 |
| 1 | 212 |
| 5 | 596 |

即使没有候选，仍会注入 45 字符的搜索收据。SessionStart 的项目 Memory 索引上限实测为 6023 字符（含标题）。Memory 是本组中最大的可变上下文来源，但它也可能提供最直接的历史召回收益，不能只按字符数删除。

### 3.4 Focus

三组七轮序列都在第 4、7 轮注入 Focus；每组累计 152–158 字符。用户在第二轮明确换题时，后续提醒仍引用第一轮旧任务锚，因为当前 Hook 只按轮数调度，不理解换题语义。

Focus 携带动态任务锚，提供了常驻规则没有的事实；但“正常深入”和“明确换题”也会按同一节奏触发。其净收益必须由真实行为对照确定。

## 5. P2 Clarify 桌面端 A/B

### 5.1 方法

- 使用 Codex 桌面端已有登录态创建彼此隔离的 projectless 测试任务，没有调用 `codex login`，也没有修改项目文件或 Hook 注册。
- 只改变一个变量：A 组在同一用户消息前加入现行 `[clarify]` 提醒文本，B 组不加入；两组使用相同判定合同，只允许输出 `direct` 或 `clarify`。
- 覆盖 6 个场景，每个重复 2 次：2 个模糊需求应澄清、2 个明确需求应直接执行、2 个续接消息应直接执行。A / B 各 12 次，共 24 次模型调用。
- 这是对“信号内容是否改变行为”的隔离测试，不冒充真实 Hook 注册链路测试；P1 已单独验证现行 Hook 的触发和注入内容。

### 5.2 结果

| 组别 | 正确判断 | `clarify` | `direct` | 无法解析 |
|---|---:|---:|---:|---:|
| A：带 `[clarify]` | 12/12 | 4 | 8 | 0 |
| B：不带信号 | 12/12 | 4 | 8 | 0 |

- 12 组配对结果零分歧；Clarify 信号在本样本中没有改变任何一次澄清 / 直接执行判断。

### 5.3 实施结论

经用户授权，候选镜像已删除 Template 与 dogfood 的 `clarify_reminder.py`，dispatcher 和受管资产不再登记或调用它，`AGENTS.md` 保留“一次一个问题 / 大而模糊时按语义判断”的原生规则，说明文档明确 Clarify Hook、字符串 gate 和 `[clarify]` 注入已经退役。Show State、Memory、Focus 未随之联动修改。

## 6. P2 Show State 桌面端 A/B

### 6.1 方法

- 使用 Codex 桌面端现有登录态创建 24 个全新 projectless 隔离任务；没有调用 CLI 或要求用户重新登录。
- A 组收到现行格式的状态汇总：`branch=codex/ia08 | dirty=3 | ahead/behind=1/0 | skeleton=v1.4.31`；B 组不收到状态。其余判定合同和用户请求相同。
- 覆盖 6 个场景，每个重复 2 次：未提交状态查询、上游领先 / 落后查询、提交推送安全、明确文件修改、概念解释、既定测试续接。A / B 各 12 次，共 24 次有效模型调用。
- 曾尝试复用已归档的 Clarify 测试任务，但 follow-up 轮没有生成可读取的 assistant message；该批运行全部排除，不计入结果。随后改用上述全新隔离任务。

### 6.2 结果

| 场景 | 配对数 | A：有状态 | B：无状态 | 行为是否改变 |
|---|---:|---|---|---|
| 查询是否有未提交改动 | 2 | 直接回答 | 先检查 Git | 2/2 改变，符合预期 |
| 查询相对上游领先 / 落后 | 2 | 直接回答 | 先检查 Git | 2/2 改变，符合预期 |
| 提交并推送前的安全判断 | 2 | 先检查 Git | 先检查 Git | 0/2；汇总不能替代变更清单 |
| 明确文件修改 | 2 | 直接继续 | 直接继续 | 0/2 |
| 概念解释 | 2 | 直接回答 | 直接回答 | 0/2 |
| 既定测试续接 | 2 | 直接继续 | 直接继续 | 0/2 |

- A、B 各 12/12 符合预期，零解析失败。
- 12 组配对中 4 组发生行为变化，全部来自用户直接询问 Show State 已提供的字段；B 组会先检查 Git，A 组可直接回答。
- 提交 / 推送场景中两组都坚持检查具体 Git 变更，说明 Show State 没有提供额外的提交安全闭环，也没有诱导 Agent 跳过检查。
- 6 组与 Git 状态无关的任务中 A / B 完全一致，本样本没有测出明显干扰；但 P1 已证明每轮仍固定支付 80 字符。

### 6.3 候选结论

Show State 不是像 Clarify 一样“零行为收益”：它能在直接状态查询中省去一次 Git 检查，因此不应整项退役。用户已授权按最小范围处置：候选 Template 与 dogfood 已移除 UserPromptSubmit 的每轮 `prompt-state` 路由，保留 SessionStart 的一次初始状态；执行提交、推送或确需最新状态时，Agent 仍通过 Git 工具取得精确证据。

## 7. P2 Memory 桌面端 A/B

### 7.1 方法

- 使用 Codex 桌面端现有登录态创建全新 projectless 隔离任务，没有调用 CLI 或要求用户重新登录。
- A 组收到现行语义的项目 Memory 索引或候选 + 模拟成功读取的正文，B 组不收到 Memory；其余判定合同和用户请求相同。
- 覆盖 6 个场景，每个重复 2 次：不可凭常识推断的历史事实、既有执行约束、零候选收据、无关候选、明确过期候选、词面相似但实体错误的候选。A / B 各 12 次，共 24 次有效模型调用。
- 首轮另有 4 次“嵌套 AGENTS”召回任务。B 组被系统级既有记忆污染，也能直接回答，因此整组排除并用不可猜测的合成项目事实替换；总计创建并归档 28 个任务。
- 结果以 `action + answer` 判定，不采信模型自报的 `memory` 字段：部分 B 组在没有注入 Memory 时仍自报 `used` 或 `ignored`。

### 7.2 结果

| 场景 | 配对数 | A：有 Memory | B：无 Memory | 结论 |
|---|---:|---|---|---|
| 不可猜测的历史事实 | 2 | 正确回答 41 天 | 明确要求查找 | 2/2 有收益 |
| 已确定的登录约束 | 2 | 正确回答“复用桌面端、禁止重复登录” | 明确要求查找 | 2/2 有收益 |
| 零候选收据 | 2 | 正常回答无关问题 | 正常回答 | 0/2 行为变化 |
| 无关候选 | 2 | 忽略候选并正常回答 | 正常回答 | 0/2 行为变化 |
| 明确过期候选 | 2 | 引用旧结论但要求核实 | 因缺事实要求查找 | 2/2 安全改变，未误答当前状态 |
| 词面相似、实体错误 | 2 | 错把行情 snapshot worker 当作 Skill 角色 | 因缺事实要求查找 | 2/2 受到误导 |

- 12 组有效配对中：4 组获得直接召回收益，2 组受到错误候选误导，2 组因过期标记转为核实，4 组无行为变化。
- 零候选时固定注入的 45 字符收据没有测出行为收益。
- Memory 不是零收益组件，不能整项退役；但当前候选正文会被 Agent 当作答案依据，词面命中跨实体时存在真实误导风险。
- 本实验隔离验证上下文内容对行为的影响，不冒充真实 Hook 注册链路测试；P1 已单独验证候选数、字符成本和 SessionStart 索引上限。

### 7.3 候选结论

现有证据不支持“保持原样”或“整项退役”。下一步应拆开处置：保留项目历史召回能力；评审是否取消零候选收据，并为 UserPromptSubmit 候选增加实体一致性 / 过期性护栏。方案未获授权前不得修改 Memory 产品实现。

### 8.3 实施结论

Focus 与 Clarify 的证据结构相同：P1 证明它在第 4、7 轮周期注入 152–158 字符，且明确换题后仍携带旧锚；P2 没有测得 on/off 行为差异。经用户授权，候选 Template 与 dogfood 已删除 `focus_reminder.py`，dispatcher、Hook 注释和 managed contract 不再登记或调用它，根 `AGENTS.md` 不再常驻 `[focus]` 响应规则。

用户手动调用的 `$focus` Skill 保留，但已与自动 Hook 解耦：它只在显式调用时查看、设置、清除手动任务锚并对照近期对话自检；不存在锚时不得静默创建，旧 `session` / `turns` 字段只兼容读取，不再宣称后续消息会自动捕获或提醒。主动澄清参考文档继续保留原受管路径以避免制造文档资产迁移，但已删除 Focus 信号章节并明确两个自动 Hook 均已退役。
