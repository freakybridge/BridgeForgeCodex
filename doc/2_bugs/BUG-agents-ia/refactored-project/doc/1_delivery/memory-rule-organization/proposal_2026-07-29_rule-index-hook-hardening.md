# Rule 索引 Hook 上游增强建议

> 状态：已采纳（批次 A 已实施；批次 B/C 暂缓）  
> 候选目标：`templates/codex/hooks/rule_index_check.py`  
> 来源：下游长期运行项目的通用 rule 治理实践，已脱敏

## 1. 结论

建议 BridgeForge 吸收下游增强版 `rule_index_check.py` 的通用能力，但禁止整文件覆盖。
应先把能力拆成小批次，并分别验证误报率、执行成本和跨宿主边界。

当前模板主要检查 `AGENTS.md` 规则索引与 `.codex/rules/*.md` 的集合一致性；
下游实践进一步覆盖索引作用域、Markdown 指针、rule 到 `doc/` 的依赖方向、
rule 删除授权和全量审计。这些问题不依赖具体业务领域，具有上游产品价值。

## 2. 传播四问

1. **属于哪一层**：本文件是元文档提案；若采纳，实现属于
   `templates/codex/hooks/` 产品层。
2. **是否应进入模板**：通用能力应进入模板，项目专属白名单和文案不得进入。
3. **是否需要版本与 CHANGELOG**：本提案本身不 bump；产品实现落地时必须 bump，
   并新增 `[product]` CHANGELOG 条目。
4. **是否需要 dogfood**：本提案不改 hook；产品实现落地时必须同步
   `.codex/hooks/rule_index_check.py` 并运行 dogfood 验证。

## 3. 差异概况

| 维度 | 当前模板 | 下游增强版 |
|---|---|---|
| 规模 | 约 148 行 | 约 419 行 |
| 运行模式 | PostToolUse、`--pre-commit` | 另增 `--audit-all` |
| 索引检查 | 入口与 rules 集合一致性 | 限定索引章节并剔除非语义注释 |
| 本地指针 | 未覆盖 | 检查 Markdown 本地文件指针 |
| 依赖方向 | 未覆盖 | 检查 rule 对 `doc/` 的依赖 |
| 删除治理 | 未覆盖 | 检查 rule 删除授权 |

行数差异不代表应整体搬运。新增阻断面必须逐项证明其通用性。

## 4. 建议直接吸收

### 4.1 限定规则索引作用域

模板不应从入口全文搜集 `rules/*.md`。示例、历史说明或其他章节中的 rule 路径，
不等于正式索引登记。建议只解析明确的“规则索引”章节。

验收：

- 索引章节内登记的 rule 被识别。
- 其他章节示例中的 rule 路径不计入索引。
- 索引章节缺失或结构异常时给出确定诊断，不静默猜测。

### 4.2 忽略 HTML 注释中的非语义内容

被 HTML 注释包裹的旧链接、模板示例和迁移残留不应触发死链或索引命中。

验收：

- `<!-- ... -->` 内的路径不参与检查。
- 正文中的同一路径仍被检查。
- 跨行注释与多个注释块均有测试。

### 4.3 支持带连字符和数字的 Rule 文件名

rule 文件名匹配必须支持常见的 `[\w-]+.md` 形式，不能把合法的
`anti-drift-2.md` 漏掉。

验收：

- 下划线、连字符和数字文件名均能登记与核对。
- 路径逃逸、目录分隔符和非 Markdown 文件不被误收。

### 4.4 增加显式全量审计入口

建议保留日常 PostToolUse 软提醒和 pre-commit 硬闸，同时增加只读
`--audit-all`，供 BridgeForge 更新、CI 或人工审计调用。

`--audit-all` 不应偷偷改变 pre-commit 的扫描边界；两者的返回码和诊断契约必须独立。

## 5. 建议抽象后吸收

### 5.1 本地 Markdown 指针死链检查

方向正确，但必须先明确边界：

- 只检查仓库内相对 Markdown 路径。
- 跳过 URL、纯锚点、代码块和行内代码。
- 规范化路径后必须仍在仓库内。
- 锚点是否校验应单独裁定，禁止文件存在就伪称完整链接有效。

建议将解析器做成独立纯函数，并用 fixture 覆盖 Windows 分隔符、URL 编码、
括号和锚点。

### 5.2 Rule 禁止依赖 `doc/`

原则具有通用价值：rule 必须能独立承载红线，不能把运行时约束正文外包给
delivery 或历史文档。

但治理类 rule 可能需要链接设计依据。上游不应复制下游的硬编码白名单；
应先确定统一契约，例如：

- rule 正文必须完整；
- `Why` 或“依据”段允许指向 `doc/0_architecture/`；
- 禁止以“详见 doc”替代必须/禁止条款；
- delivery、bugs、archive 不得成为运行时约束依赖。

### 5.3 Rule 删除授权

删除 rule 会同时影响入口索引、跨文档指针和双宿主投影，适合设置提交闸。
但授权 token 应使用专属名称，例如：

```text
[allow-rule-delete: old-rule.md]
```

不建议复用 `[skip-rule-size]` 作为整类跳过开关；名称与权限范围不一致，
容易形成过宽逃生口。

删除检查至少应核对：

- staged 删除清单；
- 入口索引同步；
- 本地指针无残留；
- 授权 token 精确列出文件名；
- 未授权删除 exit `2`，脚本内部异常 fail-open。

### 5.4 跨宿主复用

Codex 的入口是 `AGENTS.md` 和 `.codex/rules/`，Claude 的入口与目录不同。
不要把 Codex 常量直接复制成第二份实现。建议先抽出可参数化的纯检查核心，
由宿主薄入口传入入口文件、rule 根目录和索引标题。

## 6. 暂不吸收

- 下游项目硬编码的治理 rule 白名单。
- 项目专属目录、业务词、事故记录和中文诊断文案。
- 未经 fixture 验证的复杂 Markdown 正则。
- 把 419 行下游文件整体覆盖到模板。
- 未量化执行耗时就扩大每次 PostToolUse 的扫描范围。
- 用一个宽泛 skip token 同时绕过索引、指针、依赖和删除检查。

## 7. 建议实施批次

### 批次 A：低风险解析修复

- 索引章节限定。
- HTML 注释剔除。
- 连字符/数字文件名。
- `--audit-all` 只读入口。

### 批次 B：Markdown 指针检查

- 先落纯函数与 fixture。
- 明确代码块、行内代码、URL、锚点和路径逃逸边界。
- 初期仅审计，不进入 pre-commit 硬拦。

### 批次 C：依赖方向与删除治理

- 先形成 rule 到 doc 的正式依赖契约。
- 使用专属删除授权 token。
- 观察误报后再接入 pre-commit。

## 8. 验证矩阵

| 场景 | 预期 |
|---|---|
| 索引缺文件 | pre-commit exit `2` |
| rules 有未登记文件 | pre-commit exit `2` |
| 非索引章节出现示例路径 | 不计入登记 |
| HTML 注释含旧路径 | 忽略 |
| 连字符/数字 rule 文件名 | 正确识别 |
| 本地 Markdown 文件不存在 | audit 报错 |
| URL、纯锚点、代码块路径 | 不误报 |
| rule 用 `doc/` 替代红线正文 | audit 报错 |
| 合法设计依据链接 | 按正式契约放行 |
| 未授权删除 rule | pre-commit exit `2` |
| 精确授权且索引同步 | 放行 |
| 无入口或无 rules 目录 | 自门控 no-op |
| hook 内部异常 | fail-open 并给诊断 |
| BridgeForge dogfood | 模板与 `.codex` 镜像一致 |

还必须记录基准耗时，至少覆盖小型、中型和大量 rule 的仓库；不能只证明结果正确，
却让每次编辑触发明显卡顿。

## 9. 风险

- 扫描范围扩大导致 PostToolUse 或 pre-commit 变慢。
- Markdown 正则对代码示例、括号和锚点产生误报。
- rule 到 `doc/` 的边界未定义就硬拦，可能压制合法设计依据。
- 删除授权 token 范围过宽，变成绕过所有检查的后门。
- Codex 实现先行但 Claude 未抽象，形成双宿主行为漂移。
- 产品 hook 更新后漏同步 BridgeForge 自身 `.codex` dogfood 副本。

## 10. 推荐裁定

接受为“可抽象后通用”的上游候选，不直接复制下游文件。

先实施批次 A；批次 B、C 分别通过 fixture 和误报审计后再进入硬闸。这样保留
下游实践的治理价值，同时避免把项目历史复杂度原样扩散到所有 BridgeForge 用户。

## 11. 采纳收据

- 已实施：索引章节限定、`--audit-all` 只读入口；Codex / Claude 模板与 BridgeForge
  `.codex` / `.claude` dogfood 镜像同步。
- 已验证：下游 fixture 覆盖索引外示例忽略、审计模式拦截漏索引、索引章节缺失时的
  确定性诊断。
- 保持暂缓：Markdown 本地指针、rule 到 `doc/` 的依赖契约、rule 删除授权。
