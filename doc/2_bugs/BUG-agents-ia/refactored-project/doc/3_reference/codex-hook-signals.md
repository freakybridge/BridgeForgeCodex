# Codex 主动澄清行为契约

> 本文是 bridgeforge-codex 的主动澄清行为参考。文件名为兼容既有受管资产保留；当前已不承载任何自动 Hook 信号契约。

## 主动澄清（无 Hook）

目的：防止新的、大而模糊的需求在目标、范围或验收尚未收敛时直接进入实现。

处理用户请求时：

1. 先判断当前消息是否真是新的大需求。
2. 琐碎修改、原任务续接或细节完整时直接执行。
3. 只有缺失信息会实质改变实现或验收时，才说明当前理解、可选路线、推荐路线和理由，并只问一个最关键问题。
4. 能从本地事实安全确定的内容先自行核验，不把可查事实交回用户。
5. 连续确认每满 3 个问题必须暂停并总结已经确定、仍待确定和已排除的内容。
6. 超过 6 个问题仍未收敛时，必须改写成需求或验收草案，让用户核对整体，而不是继续逐题追问。
7. 目标、非目标、触发条件、验收、合理假设和剩余风险已经说清时必须停止追问。

需要落盘需求并完成用户试用闭环的大需求进入 `$develop`；评估或咨询类任务直接给结论和风险。

不得把本规则解释为“所有请求都必须先走确认卡”；Clarify Hook、字符串 gate 和 `[clarify]` 注入均已退役。

## 为什么不把完整流程常驻在 AGENTS

根文件只保留必须常驻的判断红线，澄清细则按需读取。Clarify 与 Focus 自动 Hook 均已退役；Agent 直接依据当前对话判断是否需要澄清和当前主线，手动任务锚检查由 `$focus` Skill 承担。

## 调试

调试时验证 Agent 是否按语义正确区分直接执行与主动澄清。记录输入类别、预期行为、实际行为和关键理由；禁止用一次正确响应证明长期稳定。
