# summary 建议与归档边界

> 仅当主入口发现 Rule / Hook 候选或完成事项归档候选时读取。这里只产出建议，不改文件。

## Rule / Hook 候选

候选必须来自当前上下文与完整可见对话中的重复风险，且同时具备稳定触发条件、明确承载者
和可验证收益。一次性事故、仍在变化的实现细节、缺少证据的猜测不得上升为建议。

每项按以下格式输出：

```text
候选: <Rule 或 Hook>
问题与证据: <重复风险和对话/事实源依据>
触发条件: <何时生效>
建议承载者: <AGENTS / 目录 AGENTS / 命令规则 / Hook>
建议约束: <必须 / 禁止，或可机判硬闸>
事实源关系: <链接、投影或为何不存在重复事实源>
误伤风险与验证: <边界场景和后续开发验收>
状态: 等待用户采纳；未写入；未实现
```

`$summary` 禁止创建或修改 Rule、AGENTS、Hook、配置、测试以及项目或原生 Memory。用户采纳
候选后，由其他开发方法重新确认范围、实现并验证；本次建议不是实现授权。

## 归档候选

只检查当前交付关联的 `doc/1_delivery/` topic 与 `doc/2_bugs/`。候选必须满足验收条件已完成、
用户已明确验收且没有 blocker。只输出路径、验收依据和 `请另行调用 $archive-scan`。

禁止自动调用 `$archive-scan`、执行 `git mv`、移动文档或更新 `doc/README.md`。没有候选时
明确报告“无归档候选”。
