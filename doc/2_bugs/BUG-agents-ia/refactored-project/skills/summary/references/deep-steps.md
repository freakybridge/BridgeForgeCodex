# /summary / $summary 深档步骤 SOP

> 仅在 `../SKILL.md` 命中对应低频步骤时读取该节。日常总结不要预加载整份文件。

## §旧碎片候选 — 只分析，不改文件

当多个旧 memory 疑似回答同一个稳定问题时，`$summary` 只生成候选簇。相似文件名、共享
标签或文本相似度只能作为候选依据，不能决定权威结论。

每个候选簇必须包含：

```text
候选簇: <稳定问题或簇编号>
建议的规范目标文件: <project-memory-relative-path>
来源文件:
  - <path-a>
  - <path-b>
重复结论:
  - <共同结论>
冲突或疑似过时结论:
  - <冲突、时间语义或“未发现”>
建议保留内容:
  - <当前有效结论、原因、范围、例外、权威链接>
建议删除文件:
  - <仅列已被建议目标完全吸收的来源文件>
```

只报告候选，不写规范目标、不改来源文件、不重建索引。禁止自动合并、删除、移动或把旧
文件复制到 memory 内部 archive。冲突或权威性无法判断时，明确请求用户裁决，不机械拼接。

## §独立整理任务 — 仅处理用户确认的具体批次

本节不是 `$summary` 的自动步骤。只有用户明确确认了候选簇、规范目标和来源文件的具体
批次后，才启动独立整理任务；授权不得扩张到相似但未列入批次的文件。

1. 重新读取确认批次的全部来源、规范目标和权威代码/设计文档。
2. 将当前有效结论、原因、适用范围、例外和权威链接重写成一份连贯正文；禁止机械拼接。
3. 遇到新旧结论冲突、时间语义不清或无法判断权威来源时立即停止，并单独请求用户裁决。
4. 通过当前项目的确定性 writer 或已确认的项目级写入机制更新规范目标；只有写入成功且
   内容核对通过后，才删除本批次中已被完整吸收、且用户已批准删除的旧碎片。writer 收据
   已包含索引重建时禁止随后重复 rebuild。禁止留下会
   继续参与加载或检索的 memory archive 副本；恢复渠道是 Git 历史。
5. 使用 bridgeforge-codex 唯一宿主目录 `.codex`，严格按以下
   顺序校验，禁止并行、禁止切换到另一宿主：
   1. writer 已返回成功 `rebuild_command` 时复用该收据；否则只运行一次
      `.codex/scripts/memory_rebuild_index.py`。
   2. 只有 writer/显式重建返回成功后，才运行 `.codex/hooks/memory_lint.py`。
   3. lint 成功后再检查失效链接、重复主题与本批次 Git diff。

若当前宿主的 `memory_rebuild_index.py` 失败，立即停止；必须把同宿主的 `memory_lint.py`
标记为“跳过”，禁止继续 lint 或宣称整理成功。任一后续检查失败也只能报告未通过，不得
扩大删除范围补救。

## §Rule-memory 对账 — 只产出候选

仅当本轮实际新增或改写 rule 时，对该 rule 直接相关的 memory 做局部对账，禁止全量扫描。

| memory 现状 | `$summary` 输出 |
|---|---|
| rule 已完整吸收，且 memory 不再提供 why、案例或范围细节 | 列入旧碎片候选，不删除 |
| memory 是 rule 的案例或 why 支撑 | 保留，并核对 rule 的一行 `Why` 链接 |
| 旧结论疑似被新经验取代 | 列出冲突和疑似过时结论，等待裁决 |

内容上升为 rule 不等于可以删除支撑它的 memory。任何删除都只能进入用户确认后的独立
整理任务。

## §归档候选 — 交给 archive-scan

只检查本轮关联的 `doc/1_delivery/` topic 与 `doc/2_bugs/`。候选必须同时满足：全部验收
条件已满足、用户已试用或明确验收、没有未解决 blocker。代码、测试、审计或 Git 收据
不能替代用户验收。

输出清单：

```text
归档候选:
- <delivery-or-bug-path> — <验收收据；用户验收；blocker 状态>
后续动作: 请另行调用 $archive-scan
```

`$summary` 到此停止归档动作：不调用 `$archive-scan`，不执行 `git mv`，不移动文档，
不更新 `doc/README.md` 或任何归档索引。没有满足条件的候选时，明确报告“无归档候选”。
