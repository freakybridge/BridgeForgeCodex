# 执行环境与权限恢复

同步开始前读取。继承根 Skill 的调用级确认上限，已有授权和平台自动批准直接复用；可能人工批准的主动权限请求计入同一预算，不能重置次数或替代缺失业务决定。

## 在有效预览前确定执行环境

1. 提升权限须有当前项目的具体本地写入限制证据。可复用平台明确的当前 `.git` 只读限制，或可核对的文件拒绝，例如 `.git/bridgeforge-git-sync.lock`、`.git/FETCH_HEAD`；据此在首次有效预览前选择获准的沙箱外环境，不创建试写探针。
2. 没有证据不推测提权。裸 Permission denied、仅发生于 fetch、publickey/password/keyboard-interactive 都不足以认定本地写权限问题。
3. 只为本项目受管入口申请最窄可复用范围，不分别为 Git 子命令审批。一次确认无法齐备平台许可与业务决定时停止，不默认接受或追加请求；平台额外强制 UI 不由 Skill 控制。
4. 只读审阅与必要决定完成后，最终无分析预览、完整分析生成、带分析预览和实际 release 必须在同一宿主进程内连续编排，使用同一沙箱/权限、账户、环境变量与工具链。先完成模块、序列化等初始化，再开始这一最终段；仅两个命令都在沙箱外不足以证明环境一致。

前面的只读调查可跨工具调用，但其分析文件不是最终执行凭据。最终宿主中先取得当前无分析预览，核对实际变化路径、前后内容摘要、输入角色、包归属、版本与已审阅事实及用户决定一致，再从已审阅的语义判断重新生成完整分析；不能只修补旧 fingerprint。配置、证据或兼容性影响有新变化时停止或按根 Skill 唯一剩余确认处理，不自动接受。

最终宿主进程被中断、无法继续或执行权限改变时，整段重新开始，不把另一个工具调用的旧分析当作已核验凭据；保留可复用且仍适用的用户决定。重新取得实际输入、完整分析与带分析预览属于恢复校验，不构成新的业务确认；不能借此追加一次权限请求或重置确认预算。源码、Git 状态、环境或证据真实变化仍由 Rust 硬闸阻断，流程不能承诺任何现场都必定发布成功。

## 运行中发生具体本地权限错误

普通同步在新的获准环境以完全相同的 repo-local 命令重试一次。release 不携带旧环境分析直接重试：先在新的实际执行环境重新运行无分析预览，核对真实 diff、对象/级别/理由/目标、授权及证据，再生成完整分析；带分析预览为 release-planned 后，接续同一受管 release 入口。这是一轮权限恢复，不再追加用户确认；恢复后同步仍失败则停止。

语义未变的决定和用户来源可复用；实质新风险按根 Skill 的剩余确认机会处理，用尽则停止。不得只替换旧 JSON 的 fingerprint，不得把旧环境 passed 证据改绑为新环境已通过；新证据不可取得时停止。不得改 ACL、扩大目录、修改 TEMP/TMP/LOCALAPPDATA 等变量伪装环境，或换成手工 Git。

| 错误证据 | 动作 |
|---|---|
| 明确文件/元数据写权限限制 | 按上文确定上下文，普通同步原命令、release 完整重分析后接续；最多一轮恢复 |
| TLS/SSL、超时、连接失败 | 报告原始网络错误并停止本轮自动同步，不套用权限重试、不改 TLS/Git 配置 |
| 凭据/鉴权、分叉/冲突、Hook/版本/产物失败 | 保留现场并停止，不因发生于 fetch/commit 而重试完整同步 |

受管入口统一执行 fetch、ahead/behind、安全 stash、pull --ff-only、版本事务、必要构建、add/commit/push 和核验；版本、manifest、产物及真实构建收据纳入回滚事务，pre-commit 只读。普通同步不自动升版，纯骨架更新不升级业务版本。

用户明确再次要求重试时复用有效授权和未变化证据，核对当前状态后继续；不能把失败伪报为成功。CLI 的 push 失败后远端复核属于原事务保护，不在 Skill 外额外组织完整同步，不清除 stash 或 guard。
