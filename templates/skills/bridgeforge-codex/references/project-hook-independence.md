# 项目 Hook 独立维护

仅在用户询问或明确要求开发、迁移、诊断项目 Hook 时读取。普通骨架维护不执行项目 Hook 的编译、迁移或业务验证。

- 公共 Hook 的源码、构建、安装和带 `bridgeforgeCodexId` 公共前缀的注册由骨架维护；项目 Hook 的源码、依赖、程序、收据和注册由项目维护。
- 这一边界固定在代码中，不依赖策略文件。旧 `.codex/project-hook-policy.json` 和 `.codex/project-hook-migrations.json` 原样保留、忽略，不再生成提示或完成状态；旧迁移命令已退役。
- 项目在自己的开发流程维护独立 Cargo.toml、Cargo.lock、main 和锁定构建入口，不依赖骨架 workspace 或内部源码。产物进入 `.build/`，项目自行安装并维护 native Hook 注册。
- 同步器更新公共注册时保留项目 handler、事件、matcher、参数及扩展字段，不根据脚本文件名猜测归属。归属冲突或未知公共身份应停止，不能覆盖。
- 旧项目程序及收据不会随公共布局迁移搬移，已有注册不会自动改路径。项目若需迁移，须在该项目明确授权后实施并验证完整调用链。无法确认旧目录中资产归属时保留并报告阻断，不扩大删除范围。

项目维护须验证原输入输出、退出码、超时、Windows 隐藏启动及业务行为。骨架更新成功只证明公共资产同步成功，不证明项目 Hook 的业务行为已验收。
