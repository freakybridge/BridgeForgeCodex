# spinoff — 拆出前置任务

1. 确认前置问题 B 确实阻塞主任务 A，且值得独立处理。用户已经明确要求拆出时直接继承决定；否则只确认是否拆到新对话。小前置留在当前任务，不阻塞的事项按用户意图记录 TODO。
2. 按 summary switch 流程完成经验沉淀及 doc 交接。保存 A 的目标、已有决定和授权、完成进度、验证、阻塞 B 的原因及解决 B 后的下一步；复用当前主题事实源，不写会话状态快照。
3. 生成可粘贴的新对话提示词，说明 B 的问题、已知事实、排除项和验收条件，引用 A 的仓库相对交接路径。明确只解决 B，不扩大主任务范围。
4. 附回程指引：“完成 B 后更新同一交接文档；回到主任务对话或新对话，读取 <交接路径>，核对当前代码和证据，再按已有授权继续 A。”
5. 读回交接和必要索引后返回实际路径、提示词及回程指引。不自动创建对话，不提交、推送；需要换机时用户另行 git-sync。

缺少拆分授权或无法说明阻塞关系时不写交接。写入失败时说明实际缺口，不生成虚假路径；不再调用已退役的 snapshot / resume。
