# develop — 共用开发与交付流程

## 定位与边界

复用已有需求、授权和预算，按 D1–D5 完成本次任务及必要依赖。阶段是工作顺序，不是五次审批或五份记录。条件不满足的动作直接跳过，不增加“申请省略”的步骤。
规模及预算口径由 [confirm](../confirm/SKILL.md) 管理；纯咨询保持只读，本流程不授权提交、推送、发布、安装或其他项目写入。

## D1 明确任务

一次明确用户可见结果、范围、完成标准、实施授权及适用预算。已有信息直接复用，只补会改变结果的关键缺口；缺记录不等于缺授权，不重新访谈或审批。
修改前按混杂程度区分本次变更、同包已有改动、必要依赖与无关历史问题；同包来源或授权不明时先查清，不能用局部修改认证整包。

| 规模 | 共用路径上的必要差异 | 按需 reference |
|---|---|---|
| S | 主对话直接完成，默认用对话记录、简短交付 | 涉及子包或项目特殊收口时读 completion-release |
| M | 默认主对话；短任务可用对话，需要持续跟踪或交接才落盘 | 持久记录时读 ml-delivery；确需 Agent 时读 agent-execution |
| L | 唯一任务记录保存阶段、依赖和完成条件；按依赖分段，整体预算一次约定 | 读 ml-delivery；确需 Agent 时再读 agent-execution |

规模决定组织方式，风险决定验证强度；小新增不自动归 L。S/M 默认预算不增加访谈或周额度计算；L 及真实超额按 confirm 处理，阶段和 Skill 切换不重置预算。
有有效实施授权就继续；只有范围、接口、验收或风险实质变化时，补齐受影响的决定。

## D2 调查与实现

1. 按实际影响核对直接调用、配置、数据流和失败路径，复用有效调查，不扫描无关全仓。普通实现细节自行处理。
2. 完成实现及项目要求的必要传播；项目特有的传播、版本和产物判断并入此次影响分析，范围未变不重复填写。
3. 默认主对话执行。只有用户或适用指令允许委派，且存在独立事实缺口或明确的并行收益时，才按 [Agent 执行](references/agent-execution.md) 安排；不因 M/L 标签机械启动 Agent。
4. 独立审查按用户、项目明确要求及关键风险触发；重写、迁移、审计自己改动等仍遵守公共 AGENTS。针对性检查不足以覆盖关键风险时安排独立验证，不为凑收据审计。是否需要及其成本在 D1/D2 判断，实际审查纳入 D3。

## D3 验证与修正

1. 以“用户动作 → 预期结果 → 所需检查”选择最小充分验证集，纳入项目必需项和受影响既有功能。已有检查优先；新增测试须覆盖真实风险，不为简单常量修改复述实现。
2. 仅字体、颜色或文案变化且不影响布局测量、交互、业务或告警含义时，核对调用点、相邻样式及必要构建；不默认全量测试、新框架或独立审计。共享布局或语义变化按实际风险补验。
3. 环境相关问题按用户实际入口核验启动、配置、编码和产物；替代环境明确未覆盖差异。必要构建只在输入变化、产物缺失/不匹配或需验证构建链时执行。
4. 一份验证安排、一组真实结果。复用仍适用的调查、检查和审计；相关源码、依赖、配置、产物、必要环境变化或证据矛盾时，只补受影响部分。主对话不重复 Agent 已完成且仍有效的检查。
5. 本次回归及阻断本次功能、安全或必要验证的问题须修；无关历史缺陷和润色单列，不自动实施或记 TODO。失败、超时、中断不算通过；先查明失败边界，不能用追加测试替代诊断。
6. 修正及适用审查结束后稳定候选，不在长构建期间交错改变输入。全量回归或额外审计须有项目要求或具体风险依据，并在预算内。

## D4 适用的版本收口

无注册子包变化且无项目特殊收口要求时跳过。否则读取 [收口与项目特殊流程](references/completion-release.md)，复用 D1 范围和 D3 证据，按真实受管能力处理版本、必要依赖/锁、记录和最终交付一致性。

- 默认复用覆盖最终内容的有效开发验证；升版新增影响或证据缺口才补构建、检查或测试。不因进入收口阶段重复验证，也不把聊天中的 passed 当作证据。
- 版本语义判断由 Agent 负责，计划校验和机械执行交给受管工具；参数、证据复用条件和终态以 completion-release 及其引用合同为准。工具缺能力时停止相关版本写入，不能手改版本、重绑旧记录或用旧 release 替代。
- 核对实际关联包，不因仅存在依赖关系就全包升版；无关历史问题不要求清零，同包和真实必要依赖的缺口仍须处理。
- 同一内容不重复升版，主程序 VERSION 不变。最终产物须对应交付内容；构建通过不代表功能、桌面或真实环境通过。
- 需要收口而未执行、失败、中断或证据失效时，本次开发未完成；保留实际阶段及继续条件，不能凭退出码 0、预览或版本数字变化宣称完成。

## D5 交付

一次更新已有唯一记录，一次说明：实际改动、验证命令或收据及有效范围、适用子包旧新版本和原因、限制及试用路径。复用结果说明依据；有已约定整体预算时报告实际使用口径，不伪报精确 token。
持久记录和反馈按 [记录与交付](references/ml-delivery.md) 维护；未要求持久记录时不补卡、TODO、独立授权文件或完成证书。
实现、工程验证、受管收口、用户验收和 Git 发布分别判断，但不机械输出无关空状态。未做的真实下游、runtime、桌面效果不得宣称通过。不自动调用 summary、用户验收、git-sync 或 release。

## 共用停止与恢复

- 只暂停缺授权、关键输入、必要能力/验证或预算不足的动作，其余已授权工作继续。恢复时从卡点接续，不重做仍有效的阶段。
- 扩大范围、启动 Agent、全量测试或再次实质修复前核对剩余预算；预计超额时先说明并暂停超额动作。修复失败计数和升级遵守公共 AGENTS，切换阶段、Skill 或 Agent 不清零。
- autopilot 继承同一任务包的整体预算和停止条件，不重套默认预算、重置累计或创建替代 Goal。
- 必需独立验证不可用时如实报告，不能宣称该项或整项验收完成。
