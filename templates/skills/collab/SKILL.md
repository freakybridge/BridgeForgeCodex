# collab — 分治协作

## 定位与边界

本 Skill 只维护拆分、委派、整合的专项规则。任务、授权、预算、验证和交付复用 [develop 共用流程](../develop/SKILL.md)，规模与预算事实源仍为 [confirm](../confirm/SKILL.md)；引用规则不意味着自动启动另一套流程或版本收口。
用户明确调用时先核对是否适合并行；已有授权和需求直接复用，不因缺确认卡重新访谈。只读请求只交付分析，不落盘或启动写入任务。

## 1. 确定是否拆分

1. 复用已有调查，只补拆分必需的接口、文件归属和依赖事实。独立事实缺口确需 Agent 时才派 light-explorer，不把研读固定设为一次委派。
2. 文件不重叠、任务无依赖且收益超过交接/整合成本时分派；有依赖的顺序执行。无法安全拆分时返回主对话继续，不硬凑并行组。
3. 在已有唯一任务记录内补拆分表、接口、已有证据及必要结果；用户要求或独立交接确有需要时才在同 topic 新建协作记录并更新索引。只读阶段使用对话。不得为了协作重复需求、预算或验收资料。
4. 展示目标、子任务文件边界、依赖与接口；范围、风险和预算未变时直接执行，不另设拆分审批。

## 2. 委派与执行

1. 独立实现交 implementation-worker；每个任务携带整体目标、明确需求、唯一文件边界、接口、已有授权/预算、有效证据和必要验证。提醒其保留其他工作者及用户的既有改动。
2. 按依赖决定并行组。主对话可继续不重叠的任务，不必为凑多个 worker 分派；拆分粒度取决于接口和职责，不机械限制文件数。
3. 只派发依赖已满足且写入边界不冲突的任务；前置任务未完成时不启动依赖它的后续写入。阻塞任务只有确认已停止写入并保存证据后，才可从当前组移出，其无关任务继续。
4. 进度与必要决定增量更新原记录，不实时重复抄写工具输出。所有 Agent 的时间/token、验证及返工计入同一预算；失败计数、授权和恢复点不因委派重置。autopilot 继承任务包约定，不重套子任务默认预算。

## 3. 整合与验证

1. 主对话处理接口、import、注册和配置等必要串联，核对实际改动和子任务结果。
2. 按 develop D3 完成整合需要的检查，复用子 Agent 仍有效的结果；不把“整合”当作重复全量测试的理由。
3. 适用的独立审查交 review-auditor，要求独立读取真实文件/diff、目标及接口，检查遗漏、回归和衔接；不以主对话总结代替真实差异。不满足触发条件时不为协作收据追加审计。
4. 审查发现的问题在原范围和预算内修正，仅重验受影响部分；必需验证不足时保留未完成状态，不伪造通过。

## 输出与停止

返回实际拆分与改动、整合检查及适用审计结果、未完成/未验证项；已有任务记录只给链接和必要增量，不另建重复收据。
缺授权、关键输入、必要验证或预算不足时只暂停相关动作，保留现场和恢复条件。不得同组交叉写入同一文件、扩大授权、用实现者自证代替必需独立验证，或自动提交、推送、发布。
