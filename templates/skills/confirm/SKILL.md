# confirm — 统一需求确认

## 定位与边界

整理需求事实与用户决定，区分需求确认和实施授权；跨 Skill 继承与暂停规则以公共 AGENTS 为准。已有完整决定和实施授权时直接交接，不为补记录重新访谈。显式要求需求落盘或任务确需持续跟踪时维护唯一记录；作为 develop 的入口核对时，不自动展开完整确认卡或 TODO 流程。

## 输入

- 用户的原始目标、点名载体、已知约束和验收线索。
- 本轮已有确认卡（如有），用于判断目标、范围、约束和验收是否仍匹配。
- 被 `develop`、`debate` 或 `collab` 调用时的交接目标。

## 核心流程

### 0. 规模与预算硬闸

本节是 S/M/L 规模、时间 / token / agent / 验证预算及验证轮次口径的唯一事实源。其他 Skill 只能读取本节或确认卡结果，禁止复制具体阈值、预算数值与计算规则。

1. 在启动访谈或高成本 agent 前，按“逻辑改动”而非原始文件数给出暂定规模；模板镜像、版本、CHANGELOG 和 manifest 等机械传播文件不单独抬高规模：
   - **S**：局部已知问题或小新增，方案基本明确、可逆，不涉及新架构、数据迁移或高风险业务规则。
   - **M**：跨模块或存在少量实现分叉，但边界、接口和验收可在短确认后锁定。
   - **L**：架构变更、数据迁移、高风险交易 / 安全规则，或存在多个会改变结果的未知项。新增功能不自动归 L。
2. 复用用户已约定预算；否则 S 默认 `20 分钟 / 8k 新增 token（估算）/ 0 个子 agent / 1 次验证 + 1 次修复重测`，M 默认 `45 分钟 / 20k 新增 token（估算）/ 最多 1 个子 agent / 最多 2 次验证`。默认额度直接适用，不为普通任务追加预算访谈、专门文档或周额度计算。L 开工前一次确认时间、token、agent 和验证轮次的整体预算；已有有效约定不重问。预算纳入调研、协作、验收面、合理返工和环境重试缓冲，禁止故意压低后逐轮追加。
3. 用户明确的预算和上限优先；必要独立验证超出默认配置时，按实际风险重核范围和预算，不能为守默认 Agent 数省略必需验证。报告 token 使用时，缺可靠计量必须标记“token 未实测”，以 agent 数、验证轮次和范围增长辅助判断，禁止伪报精确消耗。
4. 只补问会改变实现或验收的未决项；S 级最多一个，M/L 单题推进。预算按原任务累计，Skill 交接不重置。
5. 升档时重核授权与剩余预算；不足或预计超额时暂停相关动作，询问扩大预算或缩小范围，禁止静默扩张。

仅在需要新报、调整任务 token 预算或用户要求额度估算时，按[周额度预估](references/weekly-quota.md)选择系数、计算并输出：
`预计消耗约 N token，占周额度约 y%。` 默认只展示这两个数，不附区间、余额或重置时间。
系数来源、配置、假设与校准证据留在本机记录或确认卡；有已确认的临时系数时先给初估，不以缺少精确
官方公式为由反复拒绝估算。普通问答和快照文本长度限制不因此额外触发预算。

验证轮次统一口径：一轮是一次“实现或实质修复完成后，执行预定验收集并取得完整结果”的闭环；同一验收集可包含多条命令。工具中断、权限重试、日志丢失、输出通道故障，以及代码未变时补跑同一验收集，都计入时间 / token 成本，但不单独消耗验证轮次。只有根据完整失败结果再次修改实现或验收契约后重新验证，才进入下一轮。等待 agent、重复审计或重复测试仍计入时间 / token 成本；是否消耗验证轮次按本口径判断，禁止视为免费开销。

#### autopilot 任务包预算

仅用户明确选择 autopilot 托管时采用本段，普通任务仍遵守上面的默认预算。一次确认整个任务包的
token 总额度：估算包含调研、主/子 Agent 上下文、实现、整合、审计、验证、合理返工和收尾余量；
对外报告一个总数并标明统计口径、估算/实测及计量覆盖，不逐子任务或阶段追加审批。
时间只报告预估，不设时间硬上限。Agent 数量、并发和验证安排一次纳入执行约定，主 Agent 在已批准
的整体范围内调配；不对每个子任务重新套用 S/M 默认时间、token 或轮次额度，也不取消失败升级规则。
采用原生 Goal 预算停止阈值，用户需知悉在途调用和收尾可能超额；不是逐 token 精确截断或费用保证。
启动前说明子 Agent 是否计入；缺少可靠计量时不声称整体预算已验证，不静默降级或换口径。
同一任务包保持累计，不因切换 Skill、子任务、压缩或恢复清零。高成本工作前检查余量并预留收尾空间；
预计不足或平台预算耗尽时保存进度、停止新增工作并等待用户回来，不自动扩额、另开目标或逐次追问预算。
只有真实范围/风险变化或新增授权缺口才重新确认受影响部分，其余就绪任务继续。

### 1. 核验事实

1. 用户点名文件、表格、页面、报表、接口、数据库、业务流程或历史记录时，先只读真实载体及直接关联的读写 / 输出入口。
2. 表格至少核验 sheet、表头、关键日期列、公式或格式和代表性历史行；页面、报表与接口至少核验当前字段、触发入口和输出语义。
3. 区分已核实事实与未知项；只补核会影响本次结果的事实，不重复核验已完成阶段。
4. 载体不可访问时报告卡点；用户明确要求概念讨论时可以继续，但相关结论必须标为假设。

### 2. 逐项确认

1. 从真实事实中识别会改变实现或验收的要点，例如目标与范围、记录单位、用户动作与时点、字段映射、状态与例外、历史语义、非目标和验收标准。
2. 每轮只问一个要点，并使用具体、互斥、会改变实现的选择题：

```text
问题：{一个具体开发要点}
A. {基于已核实事实的选项}
B. {互斥选项}
C. {可选的第三条合理路径}
D. 其他：{用户补充真实需求}
```

3. 明确的自由文本回答直接记为决定；只有仍有歧义时追问，禁止改成选项后要求再确认。
4. 用户暂不确定时，明确该点是阻塞、授权默认还是移出范围；禁止把 Agent 自行假设记为用户决定。
5. 实际要点已确认、明确待定处理或被排除后，按下面条件决定记录载体；不为生成完整卡追问与本次结果无关的字段。

### 3. 按需记录

1. S 默认用对话；M 短任务可用对话，需要持续跟踪或交接时落盘；L 使用唯一任务记录。用户明确要求正式记录或项目明确必需时遵从。已有需求卡或实施计划足够承载目标时直接复用，不重建第二份。
2. 对话记录只需明确目标、范围、授权及完成标准；持久记录再保留必要的规模、预算、事实、业务规则、映射、修改范围、验收、风险和自动化边界。不存在的字段不填占位内容。已有相应写入或实施授权时直接记录；否则只确认尚缺决定，区分“记录但不实施”“开始实施”“仅讨论”，不重复索取已有授权。
3. 获准写入后按 `doc/README.md` 的 `delivery_layout` 保存：`flat` 为 `doc/1_delivery/<topic>/requirements_YYYY-MM-DD_<slug>.md`，`milestone` 为 `doc/1_delivery/<M>/<topic>/requirements_YYYY-MM-DD_<slug>.md`。无有效声明时只询问布局；同步索引。
4. 新建记录的 frontmatter 使用 `lifecycle: active`、`validation_status: not_started`；正文保留原始需求、授权依据与边界、交接目标及必要实施 / 验证记录。既有记录只补增量，状态按实际进度维护；禁止新写旧 `status` 字段或独立授权文件。
5. 用户显式调用 confirm 完成正式需求落盘、明确要求登记待办或项目明确要求时，读取 [TODO 合同](../todo/references/contract.md) 新增或引用唯一匹配原需求，回链完整 TODO 编号，不改写旧条目。仅由 develop 消费需求或补任务记录不自动新增 TODO。尚未开始为待执行；同时授权并开始实施时如实记为进行中。新增失败报告实际保存状态，不覆盖已有卡或伪称全部完成。

### 4. 交接

- 返回对话决定或唯一记录、未决项和授权；适用时附剩余预算。已有后续指令直接交接，不为取得确认卡重走流程。

## 输出与收据

- 事实核验阶段：已核实与未核实事实。
- 落盘阶段：确认卡路径、关联 TODO 编号及新增/引用结果、`lifecycle`、`validation_status`、S/M/L 规模、预算及 `doc/README.md` 索引更新。
- 交接阶段：目标高级 skill 和对话决定或唯一记录路径；没有落盘时不伪造路径。

## 停止条件

- 未决项仅阻断依赖它的动作；保持用户要求的只读或暂不实施边界。
- 点名载体不可访问且事实会影响需求时，报告卡点并停止确认该项。
- 卡片不匹配或过时：仅重核变化部分，保留仍有效的决定。
- 授权或预算不足时，报告已用 / 剩余预算与原因，暂停相关动作。

## 禁止事项

- 禁止一轮提出多个开发问题或附带问题清单。
- 禁止以抽象技术方案代替业务规则确认。
- 禁止未经相应授权写需求卡或实施；已有授权不得因缺卡而重新索取。
- 高级 Skill 只消费本流程的需求记录，禁止复制访谈或预算定义。
- 禁止只按改动文件数判定规模，或把机械镜像与发布元数据当成业务复杂度。
- 禁止交接时丢失已判断规模或已有预算约定；普通任务可直接说明适用默认额度，不另建预算卡。
- 禁止自动 `git add`、commit 或 push。
