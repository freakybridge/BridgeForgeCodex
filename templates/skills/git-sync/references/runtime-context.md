# 同步权限与异常处理

仅实际权限、输入或失败恢复需要时读取。正常路径见根 Skill；不要求同一宿主进程，也不把本文件扩成第二套发布流程。

## 权限与有效分析

- 依据当前平台 .git 只读声明或明确本地文件拒绝确定执行权限，不试写探针、不改 ACL。网络、TLS、鉴权失败不是本地写权限证据。
- 使用同一项目受管入口的最窄权限范围，不分别为各 Git 子命令申请。继承本次最多一次主动确认及已有授权，不因恢复、换 Skill 或换进程重置。
- 工具身份由共用预检取得；日常同步不前置准备工具或独立 self-test。工具缺失、不匹配时报告维护缺口，不自动安装、改环境或回退手工 Git。
- release 的分析绑定实际源码、配置、版本覆盖和必要执行环境。相同输入和环境可跨宿主进程；仅启动另一个进程不要求整段重来。影响分析的真实变化才重新取得预览并完整更新分析，不只改 fingerprint 或把旧通过记录改绑。
- 远端接入使用 --sync-remote，随后零写入预览与分析，实际 --release --skip-fetch 内部校验。需要独立查看完整计划时才额外带分析预览；正常执行不增加该步骤。

## 按失败阶段处理

| 情况 | 必要处理 |
|---|---|
| 明确本地权限不足 | 在获准环境继续受管入口；普通同步可原命令重试，release 先判断实际输入/必要环境是否变化，变化才重建分析 |
| TLS、网络、鉴权失败 | 报告原始错误并停止，不更改 TLS/Git 配置或把它当权限重试 |
| 分叉、快进失败、stash 恢复冲突 | 停止并保留现场与 stash，不自动 rebase/merge、选边或丢弃工作 |
| 版本/产物写入或提交前检查失败 | 由受管事务恢复本次自动写入和暂存区；无法安全恢复时保留现场说明，用户原有修改不得覆盖 |
| commit 成功而 push 失败 | 保留提交并报告未同步；不删除本地提交，不回滚已提交版本或补做开发 |
| 实际提交偏离计划、目标或终态不一致 | 停止后续推送，针对实际差异核查，不强推或制造成功收据 |

工具的既有失败后远端复核属于原事务；外层不再自动重启整个同步。用户明确重试时复用有效决定与证据，只处理实际变化。同仓库并行 git-sync 不在支持范围，不新建互斥或等待机制；其他构建/develop 事务与 Git 自身锁各按自身职责运行。
