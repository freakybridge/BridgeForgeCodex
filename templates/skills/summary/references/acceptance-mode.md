# summary accept — 验收差异

在共用 C1–C3 中加入下列内容，不重复执行普通总结。

- **C1：验收范围与已有证据。** 从当前交付记录和用户决定确定本次范围，对照必要完成条件及已有结果。已有明确验收不重复询问；必要证据缺失、冲突或 blocker 不标完成，已明确排除的场景保留未验证边界。
- **C2：正式验收记录与 TODO。** 优先补当前需求/设计/Bug 的验收段，写日期、用户决定、范围、实际依据、限制及相关完整 TODO 编号；符合合同才更新 lifecycle/validation_status。按[TODO 合同](../../todo/references/contract.md)与当前项目机器合同维护本次唯一相关条目，已读且未变的合同直接复用，不扫描结算无关事项。
- **C3：一致性。** 核对用户决定、文档状态、TODO 状态及验收链接一致；TODO 有变化时执行合同要求的只读检查。返回实际变更和影响本次验收的保留项，不列无关空状态。

仅明确发现的新独立问题按 TODO 合同去重记录，不主动寻找新问题，也不把原需求未完成项改称后续事项以绕过验收。已有条目缺少正式来源且本次获准记录决定时，按合同补最小决定记录；不为小事项补造完整需求卡。取消须保留实际用户决定和原因，不记成完成；旧 TODO 格式不自动迁移。

本模式不补跑验证、检查发布准备或自动 Git 同步；已有授权的事实记录不等于重新验证通过。
