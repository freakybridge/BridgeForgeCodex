# summary switch — 交接差异

在共用 C1–C3 中加入接续必需内容，不重复经验沉淀，不验收或结算 TODO。

- **C1：当前接续状态。** 复用目标、范围、已确认决定和已有证据；核对当前仓库、分支、基准 HEAD 与未提交改动概况。易变 Git 状态使用当前快照，不能把过往 HEAD 当作当前状态。
- **C2：可独立读懂的交接。** 保存已有授权和禁止项、已完成/进行中事项、改动概况、证据及未验证项、阻塞与恢复条件、按顺序可执行的下一步。引用既有需求/经验，不复制成第二份事实源；优先更新当前主题的交接记录，没有主题时按项目布局保存最小交接文档，不伪造需求卡。
- **C3：完整性与接续提示。** 核对下一次能依据文档继续，返回链接及提示：“读取 <仓库相对交接路径>，先核对当前代码与记录的差异，再在已有授权内从下一步继续；缺失证据如实标明。”说明本次没有执行提交推送，保存时 HEAD 不是未来同步的最终提交。

文档内部使用仓库相对路径。只记录接续真正需要且不随 Git 携带的依赖、环境或产物缺口，不复制凭证、秘密或完整日志，不把文档当作环境已恢复或发布准备已完成的证明。

交接 autopilot 时保留同一任务包、状态、预算观察、Goal 身份及进程/Agent 最后已知状态；不假设它们能跨机自动恢复，不重置额度、不重启任务。不上报与接续无关的机器信息，不写 .runtime/session_state/ 或使用已退役的 snapshot/resume，不自动创建新对话。
