# summary 三模式共用流程

## C1 整理

复用当前对话、已读文档和已有收据，一次确定范围、定位相关文档、去重并核对准备写入的关键事实。模式只增加本次需要的资料：普通总结不采集验收或交接专属信息。

优先查当前主题与 doc/README.md；仍有效且本轮已读取的内容不重读。仅事实缺口、矛盾或适用指令要求时有界补查历史/Memory；引用历史结论时核对原文、适用项目和时间，证据足够即停。Memory 不可用不阻止保存当前已有事实；不写 Memory。约束核对只限实际涉及的 AGENTS、Rule 或 Hook，不扫描整套规范。

## C2 落盘

将本次新增经验、验收或交接信息合并写入相应既有文档，保留事实、推断、失败和未验证项的区别。已有经验直接引用；没有新经验也可完成 accept/switch 自身有增量的记录，不强行另建经验文件。

经验包括实际触发条件、已确认原因、有效方法、失败尝试、证据和适用边界，不复制聊天流水账。当前交付/Bug 经验留在该主题，跨任务技术经验放 doc/3_reference/，项目知识放 doc/5_project_knowledgebase/。按项目布局必要时新建并更新唯一索引，不机械拆成三份文档或移动历史资料。

只维护当前模式授权的内容：普通 summary 和 switch 不结算 TODO 或修改验收状态。需要开发、补验或发布才能解决的缺口如实记录，不在总结中执行；prepared 或发布准备状态不是记录前置条件。

## C3 检查并结束

检查本次文档内容、差异及受影响的路径/索引，按当前模式补必要的一致性检查。没有增量且已有记录准确完整时不写文件，引用原文即可。检查发现矛盾只针对该事实补查，不重新组织测试、构建、审计或 smoke。

返回实际链接、必要限制与后续动作后结束，不汇报无关 TODO 或固定的“无建议/无归档候选”。整理过程中已经明确发现稳定重复的规则问题或符合条件的归档候选时，可简短提示；不另开候选扫描，不要求完整建议模板，不自动写规则或调用 archive-scan。规则建议仍是未采纳、未实施的建议。
