# escalate — 急停并求外援

## 定位与边界

用户主动求外援或达到公共 AGENTS 的失败阈值时，停止盲修并独立研判；不要求先试够次数，也不自动继续修复。

## 输入

- 原始任务和当前期望结果。
- 已尝试方案、每次失败证据、当前假设及其证据强弱。
- `$ARGUMENTS`：用户补充的卡点或待挑战假设。

## 核心流程

### 1. 立即急停并自查

停止当前问题的修改与修复命令，允许必要的只读取证。总结：

- 原任务。
- 已试方案及每项失败原因。
- 当前假设与对应实证 / 缺证据。
- 自己判断的卡点。

### 2. 独立研判

把 external blind-spot review 显式分派给 `review-auditor`。要求它：

1. 挑战至少一个核心假设，并指出反例或证据缺口。
2. 判断既有方案是否共享同一错误前提。
3. 按证据排序待验证假设；证据不足时说明，不凑数量。
4. 给出 1-2 条可执行路径，例如验证新假设、重新读规范、换思路、重做需求确认、转 `debate` 或 `collab`。

独立 agent 不得延续当前实现思路、附和主 agent，也不得直接修改实现代码。

### 3. 呈现报告

整合原任务、失败方案、被挑战假设、新根因排序、证据和推荐路径。明确一条推荐与理由，并列可执行备选。

### 4. 用户拍板硬闸

需要用户决定新路径时只问一个关键问题；已有明确选择或授权“你决定”时，按证据选定并从卡点恢复，不再确认开工。新路径仍受原范围与预算约束；再次失败时返回独立研判。

## 输出与收据

- 完整自查和失败证据。
- 独立 Agent 标识、被挑战假设与证据排序。
- 推荐路径、备选路径和用户选择。
- 若继续，明确下一步唯一验证动作。

## 停止条件

- 独立研判未完成或新路径未获授权时，禁止继续修复。
- 独立 agent 不可用时，明确报告缺少外部视角，不伪称已研判。
- 用户选择放弃时终止该问题。

## 禁止事项

- 禁止美化、遗漏或模糊失败记录。
- 禁止跳过自查直接派 agent。
- 禁止让外援直接看当前实现细节并沿原惯性修补。
- 禁止给出“再想想”之类不可执行路径。
- 暂停与恢复遵守公共 AGENTS，禁止重复索取已有有效授权。
