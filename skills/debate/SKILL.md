# debate — 双 agent 辩论

## 定位与边界

围绕已授权议题形成有证据的共识；需求记录由 `confirm` 维护，授权继承遵守公共 AGENTS。本 Skill 负责研读、辩论和交接，不把讨论自动转成实施。

## 输入

- 当前议题、边界、预算与已有确认卡或对话决定。
- `$ARGUMENTS`：问题现象、相关模块、已尝试方案和证据。
- 相关真实代码、规范和测试入口。

## 核心流程

### 1. 议题与授权核对

用户明确要求辩论且议题、预算充分时直接开展；仅补问影响结论的缺口。缺卡不阻断只读讨论，获准建档或实施时再由 `confirm` 整理已有决定。

### 2. 证据入口与建档

1. 获准写入时在所属 delivery topic 的 `debates/YYYY-MM-DD_<issue>.md` 记录议题、授权、预算与证据；明确只读时记录留在对话，不为建档中断讨论。
2. 主对话核对已有目标文件和证据入口，直接交给 A/B；不另启动 research Agent 或重复已完成调研。

### 3. 进行 2-3 轮辩论

1. 第一轮并行启动两个只读 Agent，并记录实际 id / name：
   - A 使用 `implementation-worker`：分析根因，提出代码级方案并评估取舍与风险。
   - B 使用 `review-auditor`：挑战 A 的假设，找边界、副作用和替代方案；至少提出一个 A 未覆盖的问题。
2. 后续轮次必须向同一 A、B 发送消息，保留上下文；只有续接失败时，才让新 agent 读取记录后接替，并更新 id。
3. 每轮都基于实际代码，实时记录双方观点。A 回应质疑并修正，B 再审；最多 3 轮。
4. 两个角色必须实质交锋，不得互相附和。

### 4. 收敛与交接判断

给出根因、推荐方案、实施要点和风险。仅讨论时交付结论即止；实施已有授权且结论未超出其边界时直接交接，未决的实质取舍才请用户决定。

3 轮后仍有分歧时，列出分歧和证据，让用户裁决，不继续增加轮次。

### 5. 实施交接

携带需求、有效实施授权和剩余预算交给 `develop`；可并行时由其转入 `collab`，禁止重复开工确认或将接受讨论结论当作授权编码。

## 输出与收据

- 讨论记录路径和 A / B agent 标识。
- 每轮关键主张、挑战、证据与方案变化。
- 共识或分歧：根因、文件 / 函数级改法、风险和待验证项。
- 用户最终选择及后续实施入口。

## 停止条件

- 关键事实或预算不足时暂停受影响的讨论；没有实施授权时禁止编码。
- 第 3 轮仍未收敛时交用户裁决。
- agent 续接失败时记录降级事实；无法可靠重建上下文就停止。

## 禁止事项

- 禁止辩论未读真实代码的抽象观点。
- 禁止每轮新建 A / B 丢失上下文，除非原 agent 已失效。
- 禁止超过 3 轮或让两个 agent 采取相同立场。
- 禁止 A/B 修改文件，或用仅讨论的授权执行结论。
- 禁止因缺卡重复询问已明确的议题和决定。
