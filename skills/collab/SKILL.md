# collab — 分治协作

## 定位与边界

处理文件边界清晰、可并行的大型改动；需求记录由 `confirm` 维护，授权继承遵守公共 AGENTS。本 Skill 统一负责并行研读、拆分、执行、整合与独立验证，其他 Skill 只交接输入并消费收据。

## 输入

- 当前需求卡或对话决定、授权与剩余预算。
- `$ARGUMENTS`：大型改动描述。
- 相关代码、文档、测试入口和 agent 并发能力。

## 核心流程

### 1. 需求与授权核对

核对需求卡、对话授权与剩余预算；缺卡交 `confirm` 整理已有决定，仅补问真实缺口。只读请求允许在已授权预算内研读、拆分，不建档或启动写入任务；进入实施前需有需求记录和实施授权。

### 2. 研读与规划

1. 必要研读分派给 `light-explorer`，复用已有调研；仅无法自行核实的关键缺口交回用户。
2. 获准写入时在需求卡同 topic 创建 `collabs_YYYY-MM-DD_<topic>.md`；只读阶段在对话内交付。容器不明时先核对文档索引，禁止新建全局 plan/refactor 目录。
3. 记录确认卡路径、目标、范围、约束、验收、拆分表和接口约定。
4. 若无法拆成文件不重叠、无依赖的并行任务，停止并报告原因，不硬凑并行组。

### 3. 展示拆分

展示子任务、文件边界、依赖、并行组与接口。已有实施授权且未改变范围、接口、风险或预算时直接分派；只有未决的实质变化才补问，普通执行安排不重新确认。

单任务控制在 3-5 个文件；粒度由依赖和接口边界决定，不重新访谈执行细节。

### 4. 并行执行

1. 把 independent implementation 显式分派给 `implementation-worker`；同一并行组同时启动多个实例，前组全部完成后才启动下一组。
2. 每个任务 prompt 必须包含整体目标、具体要求、接口约定和唯一文件边界。
3. 实时更新协作记录。
4. 修复失败计数与停止条件遵守公共 AGENTS；切换 Agent 不清零。

### 5. 整合与独立验证

1. 主 agent 处理 import、注册、配置等串联并更新协作记录。
2. 把 independent review 显式分派给 `review-auditor`，提供整体目标、接口和改动清单，要求它独立读取真实改动或 `git diff`，检查遗漏、回归与接口衔接。
3. 运行相关测试，把命令、断言、覆盖路径和 review 结论写入记录。
4. review 问题在原预算内修复；同一问题的失败次数不得因进入整合阶段清零。

## 输出与收据

- 协作记录路径、拆分表和接口约定。
- 各并行组状态与实际改动文件。
- 主 agent 串联检查、测试收据及独立 review 结论。
- 未完成、未验证或需要用户处理的事项。

## 停止条件

- 缺实施授权或无法安全并行时不启动执行 Agent；只读成果仍可交付。
- 关键决定或预算不足时仅暂停受影响部分；恢复时保留已完成工作与仍有效授权。

## 禁止事项

- 禁止同一并行组的 agent 修改同一文件。
- 禁止未定义接口和文件边界就分派任务。
- 禁止未经实施授权启动写入任务。
- 禁止用主 agent 的文字总结代替独立 review 真实改动。
- 实施时禁止省略协作记录或验证收据。
- 禁止把只读协作授权扩大为建档或实施授权。
