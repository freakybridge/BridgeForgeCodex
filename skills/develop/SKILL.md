# develop — 大需求交付流水线

## 定位与边界

先执行规模与预算硬闸，再按 S/M/L 选择成本匹配的交付路径。需求访谈由 `confirm` 完成；本 skill 不重复确认业务细节。单文件小修、文案微调、明确 bug 的一次性修复、纯咨询或只读方案必须走 S 级直接路径，不得启动完整流水线。

## 输入

- M/L 使用匹配的需求卡与对话授权；缺卡时按 `confirm` 整理已有决定。S 级不为流程补卡。
- `$ARGUMENTS`：用户的大需求描述。
- 项目真实代码、文档规范、测试入口和 Git 状态。

## 1. 规模与开工硬闸

1. 在调用 `confirm` 或任何子 agent 前，由主对话读取并应用 `confirm` 的“规模与预算硬闸”，
   输出规模、依据和预算收据；本 Skill 禁止复制具体阈值、预算数值或验证轮次定义。
2. 按下表锁定唯一路径：

| 规模 | 执行路径 | reference |
|---|---|---|
| **S 级直接路径** | 主对话直接实施并做针对性验证；禁止补需求卡或启动 Agent | 无 |
| **M 级精简路径** | 使用有效确认卡；默认由主对话 discovery 与实现 | [M/L 交付](references/ml-delivery.md)；需要 Agent 时再读 [Agent 执行](references/agent-execution.md) |
| **L 级完整路径** | 使用用户确认的完整预算与确认卡，进入分段执行 | [M/L 交付](references/ml-delivery.md) + [Agent 执行](references/agent-execution.md) |

3. S 级需要需求卡或独立审计时按 M 级核算；已有预算覆盖则继续，仅预计超额时询问。
4. M/L 先匹配需求、授权与预算；缺记录交 `confirm` 整理，缺关键决定才补问。禁止从卡片存在推断开工。
5. 有效开工授权直接进入实施；仅确认需求或明确暂不实施时保持边界，不强制追加开工选择题。

## 2. 共同执行顺序

1. S 级由主对话在确认预算内直接实现、针对性验证并交付，不读取 M/L references。
2. M/L 在开工授权后读取本模式所需 reference，完善同一需求包、执行、同步事实、验证并形成
   试用闭环；禁止重建第二份需求或扩大确认范围。
3. 普通实现细节自行处理。范围、行为、接口、验收或风险实质变化时，重核受影响的授权；用户新指令已明确决定则更新记录继续，否则仅暂停相关动作并补问。

## 3. 预算升级闸

- 准备扩大范围、启动子 agent、运行全量测试或进入第二次实质修复前，按 `confirm` 的统一
  口径核对确认卡剩余预算。
- 预计超出原任务预算时，暂停超额动作并说明扩大预算或缩小范围的影响；禁止交接时重置预算。

## 输出与收据

- M/L 的需求卡与相关设计文档路径；S 级明确记录“按规模闸免需求卡”。
- 实际改动文件及用户可见行为。
- 每条验证命令、断言、覆盖场景和独立 review 结论。
- 实际规模、预算使用状态、是否升档及原因。
- 未通过、未验证项及试用主路径。

## 停止条件

- 缺授权、关键输入或验证受阻时，按公共 AGENTS 暂停相关动作并说明恢复条件。
- 实质修复失败次数遵守公共 AGENTS；条件满足后从卡点恢复，不重跑已完成阶段。
- 独立验证不可用时允许交付，但必须明确标为未完成。
- 预计超预算的工作必须取得追加授权。

## 禁止事项

- 禁止 M/L 在需求、预算或实施授权不充分时开发；S 级不为流程建卡。
- 禁止把需求确认当开工授权，或在已有有效授权时再次询问开工。
- 禁止在已确认范围内把普通实现细节反复交回用户决定。
- 禁止超过预算后才补报，或把 agent 等待和重复验证排除在预算外。
- 禁止自动 `git add`、commit 或 push。
