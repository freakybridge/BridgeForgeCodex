# develop Agent 执行与审计路由

> 仅在 M 级确需 Agent 或 L 级时读取。
> 并行拆分与协作机制由 collab 管理，验证策略以 SKILL.md 为准。

## 1. M 级

- 默认由主对话调研与实现。
- 事实不足且无确定性替代时，可在预算内分派只读 light-explorer。
- 用户或项目明确要求，或针对性检查无法覆盖关键风险时，
  可分派 review-auditor。
- 调研与审计合计最多一个子 Agent，不为凑齐流程同时启动。
- 纯显示微调不默认启动独立审计；
  明确审计要求或关键风险按主入口重新核算路径与预算。

## 2. L 级

1. 文件不重叠且无依赖的任务交给 collab，
   传入需求卡、授权、已有证据和剩余预算，复用其整合与审计收据。
2. 有依赖的任务默认由主对话顺序实施。
   确有独立事实缺口或实现子任务时，再在授权与预算内分派
   light-explorer 或 implementation-worker。
3. L 级顺序交付由 review-auditor 独立读取需求卡、
   真实文件及 git diff；不以主对话总结代替真实差异。

## 3. 委派与收据

- 委派携带目标、文件边界、已有证据、验收和所需验证范围。
  子 Agent 复用有效结果；新增检查应说明具体风险依据。
- 主对话消费真实结果，不重复子 Agent 已完成且仍有效的检查。
- 审计无发现时仍说明未验证范围；
  必需独立能力不可用时如实报告，不伪造通过结论。
- 授权、预算、失败计数和恢复点跨 Agent 继承，不重置。
