# develop Agent 执行与审计路由

> 仅当 M 级确实需要 Agent，或任务为 L 级时读取。这里只决定角色、执行形态和 review 收据；
> 并行拆分与协作机制唯一归 `collab`，本文件禁止复述其内部规则。

## M 级例外路径

- 默认由主对话完成 discovery 与实现。
- 只有事实不足且缺少确定性替代时，才可在总预算内把只读 discovery 显式分派给 `light-explorer`。
- 只有用户或项目硬规则要求，或确定性测试无法覆盖关键风险时，才可把独立审计显式分派给 `review-auditor`。
- discovery 与审计两种路径合计最多使用一个子 agent；不得为了流程完整同时启动两者。

## L 级执行路径

1. 先判断确认范围能否拆成文件不重叠、无依赖的并行任务。
2. 能并行时交给 `collab`，传入需求卡、有效授权、已有调研和剩余预算，消费其收据；禁止重复调研、开工确认或重置预算。
3. 不能并行时，默认由主对话复用已有调研并顺序实施。确有可独立处理的事实缺口或实现子任务，且授权与剩余预算允许时，再分别分派给 `light-explorer` 或 `implementation-worker`；不为凑齐阶段交接任务。
   委派时携带目标、已有证据、授权、验收和边界；失败计数与恢复遵守公共 AGENTS。

## 独立 review

- L 级并行路径直接复用 `collab` 的独立 review 收据，禁止再次启动重复审计。
- L 级顺序路径把 delivery review 显式分派给 `review-auditor`，要求其独立读取需求卡、真实文件和
  `git diff`；禁止用主 agent 总结代替真实 diff。
- 平台无必需的独立 Agent 能力时，明确标记该验证未完成，禁止伪造收据。
