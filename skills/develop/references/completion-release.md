# develop 项目特殊收口

> 仅当项目声明结构化开发记录、发布准备或特殊收口流程时读取。
> 通用验证与交付规则以 SKILL.md 为准；具体要求以项目流程为准。

## 1. 项目要求

1. 读取项目 AGENTS 指向的真实收口入口，
   执行本任务适用的必需检查，不把工厂要求套到其他项目。
2. 项目构建、产物核验、独立审计和用户验收分别判断。
   必需检查未完成或失败时，不宣称对应工程验证完成。
3. 遵守项目已有命令及收据机制，复用仍有效的结果；
   不因选择轻量路径而绕过项目强制检查。

## 2. 结构化记录与准备

1. 项目选择 development-checks.json 等结构化记录时，
   使用其已有机制；未选择时不为本流程新增该类文件。
2. 使用 BridgeForge 独立开发检查前，先 self-test 确认
   git-sync-direct-release-v1，再按项目流程读取 --development-status。
   能力缺失时不试跑未知参数；--release-status 不提供开发收据。
3. 项目要求独立审计记录时，保存真实结论及适用指纹，
   不伪造 passed。
4. 项目明确要求 prepared 时，按其流程运行
   git-sync --prepare-release --message-file <消息文件>，
   需要审计时传 --audit-file。
   该过程不暂存、提交、推送或修改当前 VERSION。
5. 相关输入变化导致记录失效时，按项目机制补验和更新证据。
   没有上述要求的项目，以真实验证结果完成交付。

## 3. 与 Git 发布的边界

- 工程验证、summary、用户验收和 git-sync 各自负责其范围。
- git-sync / release 不以开发 JSON、prepared 或审计收据为前置；
  缺失或失效只影响相应工程证据，不变成 Git 使用阻断。
- 必要开发检查不留给 git-sync 临时组织；
  本 reference 不授权安装、部署、生产数据、账户或其他项目操作。
