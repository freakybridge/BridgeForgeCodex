# 开发收口与独立验证

开发收口负责工程质量，summary 沉淀经验，git-sync 负责保存代码与用户可选升版。读取项目 AGENTS 指向的开发清单，不把工厂特例套到其它项目。工程验证、用户验收与 Git 发布授权分别判断；没有开发 JSON 或收据不影响 git-sync / release 使用。

1. 完成项目要求的实现、必要构建和工程检查；未通过的必要开发项如实报告，不宣称开发完成。
2. 按项目已有测试/构建入口验证；不包含未授权安装、部署、生产数据或账户操作，不猜命令、不复制工厂清单。
3. 项目选择结构化开发记录时，可维护 development-checks.json 并使用独立工具。先 self-test 确认 git-sync-direct-release-v1，再运行 git-sync --development-status 读取开发指纹；缺该能力不试跑未知参数，以免旧工具进入同步路径。--release-status 不再提供开发收据。
4. 项目要求独立审计时先复核，把真实结论与指纹保存为 audit JSON；不得伪造 passed。
5. 可选兼容命令 git-sync --prepare-release --message-file <消息文件> 执行清单并在隔离快照构建候选产物；需要审计时传 --audit-file。它不改当前 VERSION、不暂存/提交/推送。该记录属于独立工程验证，不是之后 release 的前置。
6. 按实际检查、审计和用户试用证据交付。项目规定 prepared 工程记录时应取得有效记录；没有此要求时，不为 Git 升版添加开发 JSON 或前置验收。
7. 源码、依赖、检查配置改变可能使开发记录失效，按开发约定更新证据，不把失效转换为 Git 使用阻断。git-sync 只做版本/Git必要处理、受管产物构建及轻量提交检查，不调用开发验收流程。

没有 BridgeForge 的项目沿用自身质量工具并提供证据。本流程不授权提交、推送、发布或其它项目写入。
