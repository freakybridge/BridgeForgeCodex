# summary switch — 换机交接

> 完成普通模式的经验沉淀后读取。调用仅授权保存文档，不授权 Git 同步或恢复后扩大开发范围。

1. 读取 doc/README.md，优先在当前 delivery / Bug 主题内更新已有交接文档；没有主题包时用 doc/3_reference/ 下的主题交接文档，不为换机伪造需求卡。新增路径同步索引，不写 .runtime/session_state/。
2. 交接必须能独立读懂：目标和范围、已确认决定及原因、已有授权与禁止项、已完成与进行中的工作、改动文件、实际验证证据与未验证项、阻塞及恢复条件、按顺序可执行的下一步。引用已有经验/需求文档，不复制聊天全文或维护第二份需求。
3. 记录仓库、分支、保存时的基准 HEAD、未提交改动概况；明确这个 HEAD 是交接时的基准，不是随后 git-sync 的最终提交。使用仓库相对路径，避免另一台机器无法使用本机绝对路径。
4. 指出接续需要但不随 Git 携带的依赖、环境、忽略文件和本机发布准备缓存；不复制凭证、秘密或完整日志。跨机器缺少产物/准备记录必须按项目流程恢复，不能声称文档等同缓存。
5. 若是 autopilot，保留同一任务包路径、任务状态、预算观察、Goal 身份与状态及尚存进程/Agent 的最后已知信息。新机器不能假设原进程、Goal 或剩余预算自动恢复，不用换机重置额度。
6. 读回确认文档内容完整、路径和索引可用。输出一条可复制的接续提示：
   “读取 <仓库相对交接路径>，先核对当前分支、代码与文档差异，再在已有授权范围内从下一步继续；缺失证据如实标明。”
7. 明确告知：尚未提交和推送，请另行 git-sync；另一台机器同步仓库后读取交接文档。不要调用已退役的 snapshot / resume，不自动创建新对话。
