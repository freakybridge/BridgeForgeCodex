# todo — 归档新问题

## 定位与边界

必须将本次事项记录到当前项目根目录下的 `doc/0_architecture/TODO-INDEX.md`。
默认只记录，不修改代码；`todo` 负责新问题，`summary` 负责对话总结与验收收口。

## 核心流程

1. 必须核实当前项目根目录及适用指令，直接读取固定总表；禁止为选择写入位置扫描
   delivery / Bug 目录或启动子 agent。关联文档路径只作资料来源，不改变写入目标。
2. 总表存在时，必须保留已有章节、表格格式、编号规则和状态语义。必须先按记录 ID
   或同一事项检索已有条目；唯一匹配时精确更新本条，否则追加新条目。匹配有歧义时
   必须先澄清，禁止重复记账、复用编号、重排或覆盖无关内容。
3. 总表不存在时，必须创建该文件，使用标题“项目待办总表”和列
   `编号 | 日期 | 内容 | 状态 | 关联文档`；新表编号从 `TODO-001` 递增。
   已有总表不强制增加这些列；不得自动搬迁其他文档中的历史待办。
4. 必须按事项证据记录，禁止把记录视为实施或验收授权：
   - Bug：记录现象、影响、线索和待验证项，不创建独立 Bug 文档。
   - 已确认需求的附加事项：记录摘要和已有详细文档链接，不复制维护另一份详细正文。
   - 未确认的新想法：必须标明“待确认”；已有状态列不允许该值时，在内容中标注并沿用
     项目允许的初始状态。禁止自动调用 `$confirm`、创建 delivery 包或开始开发。
   - 已有详细文档维护的执行或验收状态，必须保留其权威关系，不在总表重复维护验收结论。
5. 首次创建总表或发现总表未入索引时，必须在 `doc/README.md` 登记一次入口；
   已有入口不得重复添加。除总表和必要的索引登记外，禁止写入其他文件。

## 输出与停止条件

- 输出实际修改的可点击路径、记录内容摘要和未验证项；未 commit、未 push。
- 完成归档后立即停止，不自动恢复旧主任务，也不追加扩展任务。
- 项目根目录无法确定、固定路径已存在但不是普通文件、项目约束冲突或无法安全沿用既有格式时，
  必须报告阻塞及恢复条件；禁止另选文件或覆盖现有内容。

## 禁止事项

- 禁止修改代码、Rule、AGENTS、Hook 或配置；代码问题只能记录。
- 禁止创建、读取、更新、移动或删除项目 `.codex/memory/`，也禁止调用 `$find-memory`、writer、
  rebuild、lint、duplicate、usage 或索引机制。
- 禁止直接写入或把内容路由到 Codex 原生 `~/.codex/memories/`。
- 禁止删除或覆盖既有 TODO；禁止把“btw / 顺便”等日常语气当作自动触发信号。
