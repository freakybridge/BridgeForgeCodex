# 从交接快照接续

恢复已有任务、决定和授权，不把历史记录当成新的授权，也不把短期交接写入长期 Memory。

## 选择与读取

- `latest`：运行 `.codex/bin/bridgeforge-hook snapshot latest`，读取返回的确切文件。
- 无参数：运行 `.codex/bin/bridgeforge-hook snapshot list`，只对返回候选读取必要的主题摘要，让用户选择。
- 指定文件名：只接受解析后位于当前项目 `.runtime/session_state/` 内的现有普通文件；明确指定时不自动换文件。
- 选择命令只读，完整交接优先；返回 `state-only / incomplete` 时只可恢复客观状态，不能猜测任务和授权。入口缺失或失败时报告错误，不自行刷新、安装或改用另一套排序规则。
- 完整读取选定文件；其他候选只在用户改选或当前文件缺少必要信息时按需读取，不批量加载历史对话。

## 核对与继续

1. 检查当前 Git 查询是否成功，读取 branch、HEAD 和工作区状态。新快照使用 porcelain v2；旧快照可能使用短格式，按实际语义比较，不直接比较不同格式的文本。
2. 快照标为 unknown、缺少 HEAD 或只有旧状态字段时，明确历史状态未验证；仍可依据当前现场做必要只读核验，禁止宣称代码与快照一致。
3. 即使 branch、HEAD 和文件清单相同，也不代表未提交内容相同。只读取交接中与下一步有关的文件、文档及必要 diff，核实完成项和待执行动作；不增加全仓内容指纹或重复回归。
4. 分支、HEAD 或文件发生变化时，先查变化是否影响下一步。能从当前证据消除的差异直接说明；只有未决差异实质影响范围、授权、安全或验收时，问一个关键问题并暂停依赖动作，其余已授权工作继续。
5. 汇总任务目标、关键决定、已有授权与禁止项、未验证项和下一步；在授权及当前事实支持时从第一条可执行动作继续，不再次询问是否开工。

没有快照、缺少任务目标或授权依据时，报告具体缺口；不能仅凭一份 Git 状态记录开始实施。禁止自动 stash、覆盖或还原当前改动。

## 输出

说明所选文件、当前 branch / HEAD、核对到的差异与证据缺口，以及接下来的动作。只在确有证据的范围内使用“已验证”；无需额外安排任务改名步骤。
