# autopilot — 单项目任务托管

## 定位与输入

当前对话统一接手实施和用户验收。其他对话只提供需求、方案与证据，不向原对话下发任务、唤醒它们或要求回复。
主对话负责调度和整合；按现有 `develop` / `collab` 规则使用已有 Agent 角色，不另建角色路由表。

```text
autopilot
对话链接1
对话链接2
对话链接3
```

也可用 `$autopilot 修复启动问题并完成已讨论的搜索功能`。不要求用户填写模板或重述已有决定。
调用入口表示开始准备；业务实施和 Goal 启动仍需匹配的明确授权。已有完整启动授权直接继承。

## 1. 接管与整理

1. 读取 `confirm` 的规模与预算规则。链接导入、Goal 生命周期或工具能力需要核实时，读取
   [运行衔接](references/runtime.md)；能力已核实可复用证据，不反复读历史。
2. 对指定来源提取用户最终决定、方案、授权依据、禁止项、已完成和待执行内容。建议、否决项、
   暂缓项与 Agent 自称获准的内容不自动成为任务。按目标去重，保留原任务编号或稳定映射。
3. 对照当前项目文件和必要 diff，核对项目、工作区、分支及来源是否仍在写入。来源不完整、
   业务决定冲突或现场漂移只阻塞受影响任务；不得从标题、摘要或链接猜测完整授权。
4. 形成一个任务包，列出编号、来源、目标、已有决定、依赖、文件边界、验收、状态及阻塞原因。
   关联已有需求卡而不复制维护第二份需求正文。缺口集中在当前对话由 `confirm` 补齐。

## 2. 启动预检与一次确认

1. 按任务实际需要检查：Goal 和来源读取能力、所需 Skill / Hook、运行中的写入者、写入路径、
   网络与登录、工具链、依赖、验证入口及可见的平台额度。已有有效证据直接复用。
2. 区分“已实测可用”“仅静态检查”“未验证”。入口存在不等于 Hook 已触发，规则允许不等于
   平台已放行。只读能检查的先检查；产生写入、安装或登录副作用的探针必须已有对应授权。
3. 必需条件缺失的任务不能标为就绪。离开前集中说明需要用户操作的事项；可移出本批或明确
   保留为阻塞项，其他就绪任务继续准备。不得关闭 Hook、放宽全局权限或承诺绝不中断。
4. 由 `confirm` 在同一需求包记录目标与非目标、任务表、预检、委派权限、验证安排、停止条件
   和一次整体 token 预算。按 confirm 的周额度规则汇总后仅展示 token 和预计周额度百分比；
   使用其任务包预算口径，时间只估算、不设时间硬限制，系数和假设留在内部记录。
5. 展示完整约定；用户明确批准当前版本后启动。只贴链接不能推定批准尚未展示的预算。
   默认交付为本地未提交改动；不自动暂存、提交、推送、发布或修改外部业务数据。

## 3. 建立与保持运行目标

1. 正式启动前用原生工具核对当前 Goal。没有目标时按已批准的任务包和整体预算建立正式 Goal；
   已有匹配目标则复用。其他未完成或预算耗尽目标先处理生命周期冲突，不覆盖、不伪称完成。
2. Goal 完成条件写成“实施、验证和交付约定的任务包”，用户验收留在当前对话。详细需求引用同一
   确认卡，避免把所有历史塞入目标。用户未授权定时续跑时，不创建自动化。
3. 整包保持一个目标；切换子任务、Skill、压缩上下文或恢复时不重建目标清零。不在业务主对话
   创建实验 Goal；预算阈值允许在途调用超额，不承诺逐 token 精确截断。
4. 原生 Goal 不可用时交付准备结果及具体缺口，不把普通单回合执行宣称为持续托管。

## 4. 自主执行与局部阻塞

1. 从依赖满足、权限就绪的任务中选择下一项，按优先级和依赖自行安排。小任务按 `develop` 的
   S 级路径直接处理，M/L 任务复用其交付流程；需要并行时交 `collab`。
2. 子 Agent 继承同一确认卡、任务边界、授权和剩余额度；共享目录写入不重叠。主对话负责串联
   与最终验证，子任务报告不能代替真实文件、命令和收据。平台并发上限不是预算授权。
3. 不因进入新阶段、超过预计耗时或普通实现取舍重复请示。在约定内调用 Skill 与执行验证；
   原生事件触发既有 Hook，检查其结果，不模拟成功事件或用 Hook 提示代替测试通过。
4. 在高成本工作、分派、修复重测前读取预算状态并预留收尾额度；不足时不再启动新工作。
   同一问题达到现有失败阈值时使用 `escalate` / `debate`，禁止切换 Agent 清零失败次数。
5. 授权内有证据支持的修复或替代路径自行执行；需要新增业务决定、权限或范围时，标记该任务
   及依赖任务受阻，记录恢复条件，继续其他就绪任务，不向原对话寻找“代批准”。
6. 更新同一需求包的状态、改动、验证证据与预算观察。文档同步交 `sync-docs`；关键阶段、中断
   与结束使用 `summary switch` 将交接写入当前主题 doc；复用同一任务包和文档，不自动 Git 同步。

## 5. 停止、恢复与交付

- 所有可完成任务实施和验证结束：按原编号汇总成果、实际验证、未验证项、阻塞与验收路径。
  全部 Goal 完成条件有证据才标为 complete；有必需未完成项不得伪称整包完成。
- 所有剩余任务受阻：保存证据与恢复条件，遵守原生 Goal 的 blocked 判定，不无限无进展重试。
  尚有就绪任务时，单项阻塞不等于整个 Goal blocked。
- 预算耗尽或用户停止：停止新增工作，处理本次拥有的子 Agent 和进程并保存已有结果；遵守
  平台预算优先级与用户控制，不自动追加额度、另开 Goal 或改用新对话规避限制。
- 恢复时直接读取交接文档，核对现场、任务包、Goal 与累计消耗，只重核变化部分。取消、清除和调额
  需要明确用户指令及实际支持的官方入口；失败如实报告，不直接修改原生数据库。
- 成果和后续修复均在当前对话处理。交付不等于用户验收；用户明确调用 `$summary accept`
  时才按既有验收流程关闭交付记录。未验收前保留 lifecycle: active。
